# Verification: What a slot loads from the directories above it

[← Verification index](../verification.md)

Which `CLAUDE.md` and memory files a run working in a checkout slot reads from the directories between the slot and `/`. It matters for a repository at the mount root, whose store `<mountRoot>/.uf-worktrees/` sits inside the operator's live checkout; the isolation rule itself is in `docs/agent/security/path-containment-and-spawn-argv.md`.

## Verified

- **A slot under a mount-root repository loads its own `CLAUDE.md` and not the live checkout's.** Measured 2026-10-25 for board task `a620ce84`, CLI 2.1.310 against a loopback stub API (unbilled), on `26f8124c`. Scratch layout under `$TMPDIR` mirroring the vault's: a repository whose `.gitignore` holds `.uf-worktrees/` and whose `CLAUDE.md` carries one marker, and a slot made by `git worktree add .uf-worktrees/vault-1 -b uf/vault-1` whose committed `CLAUDE.md` carries another; its `.git` file is an absolute `gitdir:` into the root's `.git/worktrees/`, as the real vault slots' are. From the slot, `env -i PATH="$PATH" HOME=<scratch> CLAUDE_CONFIG_DIR=<scratch>/.claude ANTHROPIC_BASE_URL=http://127.0.0.1:<port> ANTHROPIC_API_KEY=sk-ant-fake CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 claude -p --output-format stream-json --verbose --include-hook-events --permission-mode acceptEdits --allowedTools Grep Glob --disallowedTools 'Bash(pkill:*)' --append-system-prompt NOTICE_APPEND -- hello`, the shape `buildArgs` emits, sent one request whose only `Contents of …` block was the slot's `CLAUDE.md`; the root's marker was absent. Control: the same command run from a tracked `root/sub/` and from an untracked plain directory `root/.uf-worktrees/plain/` sent the root's `CLAUDE.md` beside the directory's own, so the walk does reach the root and the ignore rule is not what stops it. Caveat: a scratch layout, not the real vault through the app.

- **The pinned CLI drops project memory between a linked worktree and its main repository's root, and keeps `CLAUDE.local.md`.** Read from the 2.1.310 binary, then measured as above: when the cwd's git root differs from its main repository's root and lies inside it, every ancestor inside the main root but outside the worktree loses its `CLAUDE.md`, `.claude/CLAUDE.md` and `.claude/rules/`. With all three plus a `CLAUDE.local.md` at the scratch root, only `CLAUDE.local.md` reached the request, and adding `--add-dir <root>`, which the vault skill emits, changed nothing. So the result holds only while a slot is a linked worktree of the repository above it; a slot made as a clone or a copy would load both copies. Caveat: the vault has no `CLAUDE.local.md`, `.claude/CLAUDE.md` or `.claude/rules/` today (checked read-only); a `CLAUDE.local.md` added there would reach every slot, as the only copy, since it is untracked. Were the skip ever lost, the same binary carries a `claudeMdExcludes` setting (picomatch globs over absolute paths, User, Project and Local files only) that `--settings` could carry; not driven.
