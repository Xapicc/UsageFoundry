# A cycle's CLI, argv and appended notices

[← run-lifecycle index](../run-lifecycle.md)

Read before editing `buildArgs`, the cycle adapters or the appended-system-prompt notices in `src/lib/cycleInvocation.ts`, or `runs.provider` and `selectCycleAdapter` in `src/lib/orchestrator.ts`.

**Three flags ride *every* cycle's argv, not the opening one, and `--resume` restores none of them.** `--plugin-dir` is the case `architecture.md` records, and it now carries two *generated* directories beside the plugins found in the mounts: the vault skill, and the read guard `readGuard.ts` writes when the operator has switched it on. There were three; `--autocompact` was the third and is gone, replaced by `contextPruning.ts` — see [autocompact-and-compaction.md](autocompact-and-compaction.md). `--append-system-prompt` is the second — **one** flag carrying every notice, since a second one is a replacement rather than an addition: `SELF_HOSTING_NOTICE`, `DELEGATION_NOTICE`, `RENDERING_NOTICE` and `COMMIT_IDENTITY_NOTICE` always, then `TASKBOARD_NOTICE` and the run's own frozen file price list when the run has them. The two conditional ones are joined by filtering rather than by interpolation, because a run with neither has to leave that string byte-identical to what it was before either feature existed, trailing blank lines included, or every run without them pays a cold prefix on its next cycle for a notice it never got. **`--mcp-config`** is the third, and is the taskboard tool surface a work cycle is given when `taskboardForRuns` is on. It fails the most invisibly of the three: an MCP config the CLI was not handed is a child with no tools, which reads from a transcript exactly like a model that chose not to call any, so a version that passed it on the opening cycle alone would give every run a board that worked once. The **file** is written per cycle and removed in the cycle's own `finally` even though the token inside it is per run — a config left on disk is a live capability, where the token is bounded by the loop. `--strict-mcp-config` is deliberately **not** beside it: that is the chat child's flag, whose tool surface is closed by design, and strict on a run would silently strip the operator's own MCP servers out of every cycle. `TASKBOARD_NOTICE` rides the same `taskboard` value the flag does, so a run cannot be told to call tools it does not have nor have them without being told; `docs/agent/taskboard.md` carries both, and `docs/agent/security.md` what the token is worth. Each of the three fails the same way — nothing throws, no run fails, and a later cycle simply behaves like one that was never given the thing. `buildArgs` rebuilds the argv per cycle, so the correct shape is the unconditional one, and `orchestrator.test.ts` asserts each survives a `resumeSessionId`. `--effort` rides beside them on the same rule when `settings.runEffort` is set, though whether `--resume` would restore it is unmeasured; unset, it is absent and the CLI picks, which on 2026-09-25 left every Opus 5.5 run turn at `medium` although the mounted `settings.json` asked for `xhigh`.

**Which CLI a cycle is, what argv it gets and how its stdout is read are one choice, made once per cycle.** `CycleAdapter` (`cycleInvocation.ts`) names the three — `bin`, `buildArgs`, `parseLine` — and `selectCycleAdapter` in `orchestrator.ts` is the only place they are chosen. They are a set because being wrong about any one of them alone is silent in the same way: an argv built for one CLI and read back with another's parser produces a cycle with no cost, no session id and no stop reason, and the run page, the log and the exit code are then those of a cycle that finished with nothing to say. `runIteration` takes the adapter as a *required* argument beside the argv it built, for `silenceMs`' reason — a caller that could omit it would reach for a parser by default. Selection is per cycle rather than per run so that a restart picking up a run hours later reproduces the choice; the adapter caches nothing, which is why it is a frozen module constant rather than a `globalThis` key, and anything cached here later must take a new key. **There are two implementations, and `runs.provider` chooses between them.** `proposals/ProviderFallback/05-option-c-provider-at-spawn.md` sets out what a second owed — a column, a form field, an admission refusal for a run whose only limits this app cannot enforce — and all of it is in the tree. The Codex one is not a translation of the Claude one and the three places it differs are each a safety decision, not a spelling: `CODEX_PERMISSIONS` maps the run's permission mode onto a sandbox and approval pair and **never widens** (`default` narrows to `read-only`, and `--approve-for-me` is never emitted); the `pkill`/`killall` denial cannot ride the argv, so `codexRules.ts` writes it as an execpolicy file and a cycle whose denial could not be written is refused rather than degraded; and `SELF_HOSTING_NOTICE` and the commit-identity notice have no `--append-system-prompt` to ride, so they go in-band at the head of the prompt. Each of those is disclosed on the form and on the run page, because each is a way this app's own guarantees are weaker for one provider than the other. `orchestrator.test.ts` takes an ordered census of every flag on a maximal cycle, because a flag this seam drops fails nothing.

**`runs.provider` records which CLI a run was admitted as, and `null` on it is a third answer rather than a default.** It is written once, by `POST /api/runs`, from a select beside the model box; every other caller of `createRun` — a workflow node, a chat proposal, a reopened run — passes nothing and gets `null`, because none of them put the question to anybody. So the column has three states and the run page draws three: a provider, `not recorded` for a row that predates the column, and nothing else. It must never render as "Claude" when it is `null` — that is `git-and-review.md`'s distinction between a question answered "none" and a question nobody put, and backfilling the column or clearing it in a sweep would destroy it (`retention.md` carries the clause). It is named exactly twice, both on the run page: once in `How it was set up`, and once on the `needs-review` card, which is the only place in the app somebody is being asked to judge a diff and the one fact the diff does not carry. Nothing else keys on it — no gate in the merge queue, none in `runTouches`, no provider on a chat proposal, no per-cycle switch and no alternation within a run — and no cost derived from a non-Claude cycle may ever be summed into `runs.spent_usd` or a window meter, `docs/agent/architecture/data-sources.md`'s *"three data sources"* paragraph's rule about the three populations being what forbids it. `selectCycleAdapter` takes the column and answers the adapter for it, once per cycle and never mid-run — that a run never changes provider is the whole reason one `session_id` column can hold whichever id a run's own provider issued, and a second column for the second provider would be the wrong fix for a problem nobody has. `unsupportedProviderRefusal` is gone, deleted rather than edited, which is what its own doc said implementing an adapter would do. What is left in its place is narrower and still refuses at the door: `providerTerminusRefusal`, because a Codex cycle has no in-cycle cost ceiling to enforce. **Spend is the other thing the column decides.** `turn.completed` carries token counts and no money, so `providerRecordsSpend` withholds both the `+=` into `runs.spent_usd` and `reconcileKilledCycle` — whose transcripts are Claude's and would answer "no spend" for a session id it has never seen — and the run's stop reason says the spend is unknown rather than `$0`. Tokens are measured on both providers and are summed on both.

**An isolated run is told what its worktree does not isolate.** `refs/stash` is a **common** ref rather than a per-worktree one, so every isolated run on a repository pops from one shared stack — reproduced on git 2.50.1: worktree A stashes, worktree B stashes, and A's `git stash pop` applies B's entry and drops it. Across 251 runs there are 123 `git stash pop` calls and **not one** names a `stash@{n}`; eight runs left assistant text saying they had popped a sibling's work. `isolationPreamble` actively invites the belief — it says the checkout is the agent's own — so `SHARED_CHECKOUT_NOTICE` travels beside it, generated for `COMPLETION_NOTICE`'s reason, and names the clean-tree case explicitly because that is the one that surprises: `git stash -u` with nothing to stash creates no entry, so the `pop` paired with it in the agent's plan takes whatever a sibling pushed. `/tmp` gets one clause and no mechanism — it is shared by every concurrent agent and 117 paths in that corpus were used by more than one run, but not one confirmed clobber was found, and a per-run `TMPDIR` is a change to every child's environment to close a path nothing has yet taken.

**A run is told to delegate, and the instruction has a floor in it.** `DELEGATION_NOTICE` travels with `SELF_HOSTING_NOTICE`, `RENDERING_NOTICE` and the file price list under one `--append-system-prompt`, because a second one is a replacement rather than an addition — the same trap `--allowedTools` carries — and with four notices on that flag the one that would go missing is whichever the last edit did not think about, one of them being the process-safety one. It is worth its own tokens on figures that are **re-measured** rather than carried forward: over 1,194 transcripts and 49,038 deduped assistant turns across 12.3 days, priced through `pricing.ts` and split on the transcripts' own `isSidechain`, a tool call inside a sub-agent costs **5.0 cents against 13.6** on a run's own main thread, most of the gap being cache re-read at 3.0 against 8.2, and the same call costs 8.4 cents over turns 11-25, 15.7 over 101-200 and 20.4 past turn 200. The previous reading over 1,011 transcripts was 6.5 against 13.9 with 2.7 against 8.3 — the same claim, with the sub-agent side if anything cheaper. **One weakness in it is stated rather than absorbed:** sub-agents are handed the self-contained errands precisely because those are the ones worth delegating, so an unknown share of the 5.0-against-13.6 gap is the task rather than the context. What is not confounded is the within-thread gradient — 8.4 to 20.4 across turn position on the same threads doing the same kind of work — and that gradient alone is the reason to delegate. The floor is in the text rather than left to the agent: a sub-agent's opening turn averages 10.6 cents of its own, and grouped by `agentId` the invocations under five turns measured *worse* per tool call than every longer band, 6.7 cents against 4.1 at 11-25, so a run that delegated every errand would spend more than one that delegated none. That floor moved down — it was ten turns and is now about five — which is why the notice's own words still read "more than a handful of steps" **unchanged**: the string is what keeps every run in flight off a cold prefix across the deploy that re-measured it.

**A run is told a browser is already here, because the command it reaches for from memory is the one thing that does not work.** The image ships Playwright and a Chromium (`docs/agent/environment.md`) and nothing told the agents, so they ran `playwright install` — which fails, and whose failure text is "Failed to install browsers". That reads as *there is no Playwright here* and sends a run off to fetch a second Chromium into a path it can write, or to stop looking at the page it just changed. Both error strings are measured and are in `docs/verification.md`: EACCES on the root-owned link file with the sandbox off, `Read-only file system` under `UF_SANDBOX=1`, where bubblewrap binds everything outside the write allow-list read-only and no ownership can change it. So `RENDERING_NOTICE` says how to take a screenshot **and** that a refusal from `playwright install` is not evidence about whether rendering works. It names a command, which the file price list deliberately does not, and what makes that safe is the same property: the only verb near `playwright` is "run", the command is synchronous and leaves no process to clean up, and nothing near it suggests selecting a process by name. It carries **no viewport size** for the other half of that rule — `--viewport-size=1280,800` is the natural thing to write in a worked example, and the digits test refuses it, because `1280` reads as a port and the recipe further up the same prompt says to select a process by the port it chose.

**A run is told the literal value of `$TMPDIR`, because Bash expands it and `Read` does not.** The CLI's own prompt says "always use the `$TMPDIR` environment variable" and never what it holds, so a run that writes `"$TMPDIR/x"` and reads it back has to spell the directory itself, and fifteen of one month's thirty-nine `File does not exist` misses were that done wrong (`/tmp/claude/`, a session segment inserted, `/tmp/<file>`). `tmpdirNotice.ts` states the value, and the value is **derived, never typed**: the CLI's per-uid root is `join(CLAUDE_CODE_TMPDIR || os.tmpdir(), "claude-" + uid)`, so it follows `UF_AGENT_UID` and the child's inherited environment, and `/tmp/claude-1000` is only what that comes to here. Where it cannot be known the notice is **absent rather than a guess** — no managed sandbox in force (the CLI sets the per-uid directory as `$TMPDIR` only for a sandboxed command), a Codex run, no uid, or a root past the CLI's 44-byte bound — because a wrong path stated by the supervisor is the misspelled prefix again. It is taken **once, in `createRun`**, stored on `runs.tmpdir_notice` and read back on every cycle, for the price list's reason and never recomputed at the spawn: the managed policy can be edited between two cycles of a run, and a prefix that changed would be re-read at full price. It is last in the join, after the price list, so a run without it keeps every byte it had. Its digits are the uid and an absolute path, which is the price list's category rather than the standing half's: no verb beside them is `kill`, and `tmpdirNotice.test.ts` holds that. The residual risk is an agent that picks the uid as a port and matches on it, which the standing half's no-digits rule exists to prevent and this half cannot satisfy by construction.
