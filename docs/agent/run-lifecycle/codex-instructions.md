# What a Codex cycle is told before its prompt

[← run-lifecycle index](../run-lifecycle.md)

Read before editing `codexInstructions.ts`, the `project_doc_fallback_filenames` entry in `buildCodexArgs`, or anything that writes into `$CODEX_HOME` beside the rules file.

**A Codex cycle reads the same standing instructions a Claude cycle does, through the two files Codex looks for.** Codex reads `AGENTS.md`, never `CLAUDE.md`, so a Codex run in a repository written for Claude worked without the repository's instructions and without the operator's `~/.claude/rules`, and nothing said so — it reads as a model ignoring them. Two mechanisms, each measured on 0.153.4 on 2026-10-07 with `codex debug prompt-input` and markers: a repository's `CLAUDE.md`, root and nested down to the working directory, arrives through `-c project_doc_fallback_filenames=["CLAUDE.md"]` on every cycle's argv (no marker without it, both with it; a repository with its own `AGENTS.md` keeps that); and the operator's `~/.claude/CLAUDE.md` and `~/.claude/rules/*.md` are composed into `$CODEX_HOME/AGENTS.md`, Codex's global instructions, which a `codex exec --ignore-user-config` still loads. A rule's `paths:` frontmatter is Claude Code's condition and Codex has none, so it becomes a sentence above the rule rather than being dropped with the rest of the metadata — dropping it would make a Python rule read as one for every file.

**The generated file is this app's whatever it holds, and it is rewritten or removed before every Codex cycle.** `$CODEX_HOME` is the agents' own directory, so a cycle can replace the file, and a run that wrote itself standing instructions would hand them to every Codex run after it. Rewriting from the sources bounds that to the cycle that did it, and with no sources the file is removed rather than left. It deliberately does not keep a file that lacks its header as "the operator's": that is exactly the shape a planted file would take to survive, and the file did not exist before this module — Codex instructions belong in `~/.claude/rules`, where Claude reads them too. A failure to write is a log line and the cycle still runs, unlike the `pkill` rules beside it, whose absence refuses the cycle: missing style rules cost quality, a missing denial could cost every run in the container.
