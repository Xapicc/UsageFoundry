# Origin, queue order and the request log

[← run-lifecycle index](../run-lifecycle.md)

Read before editing `runs.origin` or `runs.priority` in `src/lib/orchestrator.ts` (`createRun`, `queueOrder`, `selectPromotable`, `setRunPriority`), or `src/lib/requestLog.ts`.

**A run records the gate it came through, and a pick-up is not that gate.** `runs.origin` is one of five — `form`, `chat`, `workflow`, `orchestrator-block`, `schedule` — written by `createRun` from a **required** field on `CreateRunInput`, and `origin_ref` is the record that authorised it (the proposal, the instance, the schedule, the block's node). Required rather than defaulted, and stated at the call site rather than carried on a plan object, because the whole point is that it is *recorded* rather than deduced: a default would be a deduction with a compiler behind it, and the two paths that share `planNode` — a press of Run and a schedule firing — differ in exactly this field. Provenance was previously a join across `chat_proposals`, `workflow_instance_runs` and `emitted_by` whose absence was ambiguous between the run form and a run picked up by hand, and which did not survive deleting the chat or workflow it came from; both columns are plain, `emitted_by`'s rule, so they keep reading true after that row has gone. Three of the five start an agent with nobody at the keyboard, which is what the column is for. **`reopenRun` deliberately does not write one of these values.** It creates nothing, so recording it in `origin` would lose the fact the column exists for while `created_at` went on pointing at the original creation, and a query grouped by origin over a time range would then be a lie about an audit column; it stamps `reopened_at` instead, with the request that asked for it on `request_log`. An orchestrator block's emitted runs are `orchestrator-block` even inside a *scheduled* instance, because what authorised each of those is a model's decision taken moments ago; a deferred plain node created hours later reads the instance's own copy, so a scheduled graph's late nodes stay the schedule's.

**What the queue is allowed to consider besides age.** `runs.priority` is an
integer, higher first, and `created_at` breaks every tie — so an install that
never sets one queues exactly as it did before the column existed, which is the
property that makes it safe to have. `queueOrder` is the single definition of
that ordering and `selectPromotable` is its only caller, so "what runs next" has
one answer rather than one per query. Priority is clamped to ±100 by
`setRunPriority`: an unbounded integer invites `MAX_SAFE_INTEGER` as a way of
saying "definitely first", and the row after it is then unreachable by any value
a person would type. Setting one never starts, stops or skips a run — on a
running row it means nothing until that row is queued again, which is why it
refuses nothing based on status.

**Every mutating request leaves a line, and the line is a shape rather than a dump.** `auditMutation` wraps each mutating handler at its export — not inside the handler, because a handler has several return paths and the one that would be missed is a refusal, which is the line an audit most wants. It records the method, the URL's `pathname`, the status, the id the route named (from its own params, or from the `x-uf-subject` header a *creating* handler sets and the wrapper strips), which **credential class** was used, the first hop of `x-forwarded-for`, and the duration. What it must never carry is named rather than assumed: no request body (`POST /api/runs` carries every prompt and `POST /api/login` carries the master token), no query string (where a credential ends up when somebody puts one there by mistake), no cookie or `authorization` value — `actor` says *how* a caller authenticated and never with what. Two mutating routes are deliberately outside it and say so in their own comments: the OTLP ingest, whose callers are this app's own children delivering every few seconds per run, and `/api/workflows/validate`, a POST that writes nothing and is polled while somebody draws. A third exemption is narrower than a route and is about the *table* rather than about the caller. `/api/mcp` authenticates itself — `middleware.ts` exempts the path — so a credential-free POST reaches the handler having passed nothing, and while `auditMutation` wrapped that handler from outside, every such request wrote a row and every insert evicts past the 20,000-row cap: twenty thousand correctly-refused requests, and every line naming a run that was started, a setting that was changed or a sign-in that failed is gone. Only the handler that already holds a subject is wrapped now, so the case the table exists for — a real capability whose tool call was refused — still leaves a line; `DELETE` is not audited at all, being a 405 answered before any credential is read and mutating nothing; and the refusal leaves its trace on stdout instead, where nothing is capped, so somebody hammering the path is visible without being able to push anything out of it.
