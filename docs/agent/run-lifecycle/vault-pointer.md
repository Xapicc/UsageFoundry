# The vault pointer and its holdout

[← run lifecycle index](../run-lifecycle.md)

Read before editing `vaultPointer.ts`, `vaultPointerNotice`, `vaultPointerFor` in `orchestrator.ts` or the `vaultPointer` slot in `nextPrompt`, before changing the gate's model or prompts, and before analysing the holdout.

**A run's first prompt names the vault notes that bear on its task, on half of all runs, and for most runs there are none.** The vault skill offers the operator's knowledge vault on request, and the requests did not come: over the 592 runs of 2026-09-25 to 10-25, every one of which had the skill in its list, 6 invoked it, all on two days and none in the 430 runs after, while 9 of the 12 runs whose prompt named a note opened it. So the app looks once, before the run starts, and says what it found. It is the same finding `docs/agent/dreaming/vault-skill-steering.md` made on three runs in September — availability is not what makes an agent check — taken from a month instead of an afternoon.

**The vault's search proposes and a model decides, because search alone names the wrong notes.** `vault_search.py` answered with a confident match for 493 of 530 task titles that month, and a reading of 147 of them found something worth an agent's time for 5; the script's own comments record that its abstention stopped firing as the vault grew, and leave the threshold alone on purpose. What search is good at is recall, so it is used for that: the task's titles and up to three queries a first gate call writes from the task text are each searched for eight notes, the union is cut to twenty at each note's best rank, and a second call reads the task beside every candidate's grade, size, abstract and — for a note over 3,000 tokens — headings, and picks at most three or none. `readJudgeVerdict` then holds the answer to what it was shown: a path must be one of the candidates verbatim, a section one of that note's headings, a note counts once, and three is the cap whatever the schema said.

**The judge's prompt is the strict one, and it was chosen by measurement.** Two prompts were backtested on the same 151 runs (Haiku 5.5 on CLI 2.1.310, each run's candidates drawn only from notes that existed on its day). The first asked whether a note "would help"; it named notes for 38 runs, and of its picks an independent grader called 19 useful, 36 background and 3 irrelevant, and one path it named had never been offered. The shipped one asks whether an agent who read the note "would do this task differently or faster" and says an empty list is the usual answer: 25 runs, the same 19 useful picks, 14 background, 1 irrelevant, 8 not graded, and no invented path. It found the note on 11 of the 14 runs where one was known to matter and named nothing on the 3 where the vault was known to have nothing. The figures and their caveats are in `docs/verification/knowledge-and-plugins.md`. A change to either prompt or to `VAULT_GATE_MODEL` is a change to the treatment, and goes through the same backtest.

**What reaches the run is a pointer, never a note.** Each pick is its path, confidence and size, its abstract, one line on what in it the task would use, and, for a long note, the heading to read. About 120 tokens a pick, and the abstract alone is often the whole answer. Worded as a record of what is already known rather than as an instruction, for `priorReadsNotice`'s reason: an instruction to read is the sentence agents measurably decline, and one they follow is paid for on every later turn. The section is there because twenty notes in this vault are over 10,000 tokens, and a whole read of one is re-read on every turn of the cycle.

**Its slot is ahead of the prior-read pointer, on the session-less branch only.** The vault pointer is the block more about the task, and would naturally sit last before it — but "directly ahead of the task" is the prior-read pointer's treatment in an experiment still running, and moving that block would change the arm halfway through the comparison. A resumed conversation already holds the block from the turn that opened it.

**It is resolved once per segment, before the loop, and only for a segment that opens a conversation.** Before the loop rather than beside `nextPrompt` so that a Stop pressed while the gate is answering is read by the loop's first check, before any cycle is spawned. A fresh start later in the same segment is sent the same picks: the task they were picked for has not changed. It costs the run 9 to 16 seconds before its first cycle, measured end to end against the real vault on the operator's Mac: two gate calls of a few seconds each, and searches that each rebuild the vault's index (3.7s at 2,003 notes), which is why a run is searched with at most six queries, three at a time. A failure anywhere — the search exiting non-zero, the gate silent for a minute, an answer that is not JSON — is a pointer with no picks and the failure named on the run's log; it is never a reason for a run not to start.

**Who is never considered, so is in neither arm.** `priorReadsFor`'s Codex and local-model runs and Dreaming's writer, for that function's reasons, and three more. A run on an install with the vault skill off or unavailable: that switch is the operator's answer to whether unattended agents are told a vault exists, and naming its notes is telling them. A vault with no ranked search: the pointer exists because search alone names the wrong notes, and grep would name more of them. And a run starting during a shutdown, which a classifier would otherwise hold open.

**Both children run as the agents' uid, and neither is a fifth kind of agent child.** The search is `python3 <vault>/_Meta/vault_search.py`, a script that lives in content runs can write; run with the server's authority it would hand any run that edits `_Meta/` the server's authority too. The gate is `claude -p` with `--tools ""`, `--setting-sources ""`, `--strict-mcp-config` and `--disable-slash-commands`: it reads what it is handed and answers in JSON, the operator's hooks do not fire on it, and nothing in a task's text can make it reach anything. It is spawned for its output like a review, but it has no cwd worth the name, no repository, no permission mode and no row of its own, so it is bounded the way `claudeAuth.ts`'s children are rather than by `maxConcurrentAssists`: its own deadline, and `GATE_CONCURRENCY` gates at once across the install, because runs start in bursts and each gate is a few hundred megabytes for a few seconds. Its transcripts land under `/run/uf-skills/uf-vault-gate`'s project in the metering path, so the windows meter counts them and neither the vault's project — Dreaming's corpus — nor the run's appears to have spent them.

**Its cost is priced by this app, recorded on the run, and kept out of `runs.spent_usd`.** About $0.002 a run on the backtest. `gateCost` prices the tokens with `pricing.ts` rather than taking the CLI's `total_cost_usd`, which is only as right as the pinned build's own price table: 2.1.280, the pin until 2026-10-25, did not know `claude-haiku-5-5` and priced it at a fallback rate, measured at fourteen times what 2.1.310 reported for the same call. It is kept out of the run's own spend as a review's is: the gate is given no telemetry environment, and a run whose spend its own telemetry cannot account for reads as a metering fault.

**The arm is `vaultPointerHoldout(runId)`, and it must never change.** `holdoutOf(VAULT_POINTER_EXPERIMENT, id)`: the prior-read pointer's split, drawn from a preimage of its own so that the two experiments' arms are independent, which `vaultPointer.test.ts` asserts over 400 ids. Both arms are asked, as the prior-read pointer ranks its list for both: which held-out runs *would* have been shown a note is the whole of what the comparison needs, and it cannot be recovered afterwards. Every session-less cycle a considered run opens records `vaultPointer: { arm, paths, costUsd }` on its `iteration` event, and the run's log says what was named, held back, found to be nothing, or failed. Reading the arms back is not built, and at the rate the backtest measured — a note for one run in six, an upper bound, since that sample included every run known to have needed the vault — it needs a month of runs before it says anything.
