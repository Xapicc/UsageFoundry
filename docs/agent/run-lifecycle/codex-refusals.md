# A Codex run's wall and content refusals

[← run-lifecycle index](../run-lifecycle.md)

Read before editing `refusalKind`, `isCodexUsageLimit`, `isCodexPolicyRefusal`, `refusalStopReason` or the park in `startRun` for a Codex run, or `codexWallBoundary` in `codexAccount.ts`. The rules they extend are in [parking-and-refusals.md](parking-and-refusals.md).

**A Codex run's wall is read in Codex's words and waited out to Codex's reset.** `isUsageLimit` excludes any sentence naming credits, because on the Claude path a credit balance is a spend cap that does not refill — and one of the four wall sentences the pinned Codex 0.153.4 prints (read out of the binary) is "You've hit your usage limit. Visit …/codex/settings/usage to purchase more credits", an upsell on an allowance that does refill. Read with the Claude predicate, a Codex run at its limit ended as `failed`. So `refusalKind` takes the run's provider and, for Codex alone, reads `isCodexUsageLimit` — the opening "You've hit your usage limit" — first; a Claude refusal that quotes the sentence is still read by the Claude rule. The park then takes its boundary from `codexWallBoundary` over a fresh `codexUsage()` reading rather than from `lastSpendingWindowEnd`, which reads transcript blocks a Codex run never writes and would always fall through to the ladder: the reset of the full window, the later of the two when both are full (waking at the session reset with the week full is a second refusal), the session reset when the reading — possibly minutes older than the wall — shows neither full, and null with no reading, so `refusalResumeAt`'s ladder, floor, cap and jitter still decide what they always did. The sentences name Codex and the ChatGPT plan.

**A content refusal is its own ending, with what to change in it.** OpenAI's filter refused a real Codex bug hunt on 2026-10-07 — "This content was flagged for possible cybersecurity risk…", `codex_error_info` `cyber_policy` — on its second request, after a `git status`. No wait or retry clears that, so `isCodexPolicyRefusal` makes it `policy`, `refusalDisposition` ends the run with `content-policy`, and `refusalStopReason` says it was OpenAI's decision and what the operator can change: the brief's wording ("write a failing test for each defect" reads less like security research than "demonstrate each one"), the model, or the provider. The `access_programs.cyber` tier the message names is an account enrollment on OpenAI's side; the pinned CLI only reads it, so there is no setting here to raise it. Every refusal sentence names the CLI that refused — a Codex refusal reported as "Claude Code refused the request" sent the operator to the wrong account.
