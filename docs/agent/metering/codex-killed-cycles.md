# A Codex cycle that never reports its tokens

[← metering index](../metering.md)

Read before editing the Codex branch after `runIteration` returns in `startRun`, `interruptedCycleEstimate` or `reconcileInterruptedCycles`, `readCodexCycleSince` in `src/lib/codexRollout.ts`, or `unmeasuredSpendNotice`.

**A Codex cycle's tokens reached `runs.spent_tokens` only through `turn.completed`, so a cycle that ended any other way charged the run nothing, and the one spending guard a Codex run has stopped holding.** The live `run_tokens` guard, Stop, the silence deadline and a restart all end a cycle before it reports, and `turn.failed` — the usage wall, a refusal on a later request — carries an error and no usage. The cycle's rollout had recorded every request regardless. `maxRunTokens` reads `spent_tokens + spent_tokens_est`, so a run killed at 120,500 tokens of a 100,000 limit kept its pre-cycle figure, passed `reopenRun`'s check and the pre-cycle guard, and was killed at the limit again on every reopen with its recorded total never moving. The Claude path answers a killed cycle with `spent_tokens_est`, an estimate held apart and counted by the guard (`run-spend-readings.md`); the rollout is the Codex counterpart and was already in hand, because `endCodexCycle` returns its final reading to the cycle's `finally` for the context chart.

**The loop banks that reading into `spent_tokens_est` when the cycle did not report, and into nothing else.** The `finally` keeps `endCodexCycle`'s result; once `runIteration` has returned, `!res.sawResult` adds `reading.tokens` to `spentEstTokens`. `spent_tokens` stays what Codex itself reported, as `spent_usd` stays what Claude Code measured, and `spentGuardTokens` is the sum, so the pre-cycle guard, the live tick (whose in-flight term is gone by then — nothing counts twice) and `reopenRun` all see it. `installCodexTokens` and `repoSpend` already summed both columns and are right without a change. **A cycle that reported is never banked.** The rollout's total equals `turn.completed`'s (`budgets-and-guards/enforcement-modes.md`, measured), so banking both would charge it twice, which is why the condition is `sawResult` and not "a reading exists". A run page, the runs list and the `/runs/live` tile show what the guard counts, with the banked part named: `runTokenFigures` in `format.ts` is `spent_tokens + spent_tokens_est` for a Codex run and the reported figure alone for any other provider, which writes none, and the surfaces say "64.0k tokens, 30.0k of them counted from the session log" (the runs list's narrow column says "includes 30.0k from session log" under the figure). **They show the sum because a run ended on `maxRunTokens` must not display a total under its own limit**; the run page keeps what Codex reported visible beside it, and every sentence is unchanged when nothing was banked. `LiveRunDTO` carries `spent_tokens_est`; `RunDTO` already did. Unlike `spent_usd_est`, which is a price this app derived from transcripts and is shown apart from `spent_usd`, the banked tokens are the rollout's own count, equal to what `turn.completed` reports where both exist, so there is nothing to hold apart in the display.

**A cycle no loop came back for is read from its thread's rollout, from where it began.** `reconcileInterruptedCycles` used to run `reconcileKilledCycle` for every row. That reads Claude's transcripts by session id, and a Codex session id is a thread in `$CODEX_HOME/sessions`, so it answered "nothing found" and the run's log said the cycle's spend "is missing". `interruptedCycleEstimate` sends a Codex row to `readCodexCycleSince(session_id, active_started_at)`. The tracker `beginCodexCycle` keeps lives in the dead process's memory, so where the cycle began is known only as the instant `active_started_at` holds: a `token_count` line stamped earlier is an earlier cycle's and is left out, a line with no timestamp is left out too (a floor, never a count of a past cycle), and a file longer than a final read is read from its tail because the newest lines are the interrupted cycle's. No file is "could not be read", never "no requests", and the log says so in those words.

**The ending says the count is understated, and the sentence outlives the segment that lost the flag.** `unmeasuredSpendNotice` replaced two string literals that each ended "Its token count is measured." — said of a run whose cycles had been killed. `incompleteIteration` is a local and a restart loses it, so a Codex run's later ending also reads `spent_tokens_est > 0`, which only this banking writes for Codex. The sentence says how many tokens came from the log rather than from Codex, and that a request still running when the cycle ended is not in them. It serves the `local` provider as well, which is killed by the same routes and banks nothing, so its sentence now says understated and no more.

What is not covered: a cycle whose `runIteration` throws rather than returns is dropped with its reading, and the in-flight request's tokens are never in a rollout. `codexKilledCycle.test.ts` drives the loop against a stubbed child; no real `codex` cycle has been killed and read back (`docs/verification/other-providers.md`).
