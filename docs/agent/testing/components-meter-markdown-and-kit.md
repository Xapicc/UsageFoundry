# Components: Meter, the ascii skin, Markdown and the UI kit

[← testing index](../testing.md)

Read before adding or editing tests of `Meter`, `LiveTelemetry`, `Markdown`, and the `ui/` kit (`Table`, `Disclosure`, `LimitField`, `ListView`, `AsciiFrame`, `AsciiBar`).

Four of the renderings are `Meter.test.tsx`, `LiveTelemetry.test.tsx`, `Markdown.test.tsx` and `ui/Table.test.tsx`, and they clear the same bar by the same argument: what they pin is *something the reader would act on*, wrong in a way that throws nothing and typechecks (a solid green bar that means "we don't know"; a first-party figure that reads as an addend to the transcript-derived meter beside it; a report that ends in silence because the cycle was killed with a code fence still open).

The fourth is `Meter`'s argument at a second breakpoint-shaped invariant, and it fails in two directions rather than one.

`Meter`'s announcement cases are that same file's argument reached through the accessible name rather than the fill: the hatched band is a different quantity at each of the seven call sites that draw one, the component used to compose a single sentence claiming it was unpriced models, and that sentence is false at the three money-shaped meters — where the band is spend reconciled for a work cycle that stopped before reporting — so a screen reader was handed a fluent and specific reason that did not hold, with nothing on the page, in the markup or in the types disagreeing.

What is pinned is therefore the sentence each caller announces, one row per call site named by file and label, and the mechanism-free default a caller that supplies nothing falls back to, because a default that named a mechanism is the defect again in slower motion.

The head's own two readings are the same argument once more, and the one case where the markup alone settles it: `value` lets a caller replace the head's percentage with money or a pair, the band's reading was formatted as a percentage regardless, and the two meters that do both drew a dollar amount and a percentage joined by an en dash as if they were two ends of one range. What is pinned is the pairing rather than either string — a supplied `value` is drawn beside a supplied `upperValue` and beside nothing else — because the band is now dropped from the head, the track and `aria-valuetext` together when a caller cannot spell it, and a test on the head alone would pass a hatch left on the track with no number anywhere to account for it.

`UsagePeriods.test.tsx` carries the only *caller-level* assertion of it the suite can reach — the three meters where the old sentence was false are all inside pages that no `renderToStaticMarkup` here can build — so a caller silently dropping its hint is caught at one site and understated at the rest.

`LiveTelemetry`'s provenance case is that same file's grounds once the card moved into the row of meters — "beside it" stopped being a figure of speech — and what carries it is no longer a sentence: the three-line footnote that stated the separation was deleted in the operator's VisualEdit pass of 2026-09-04, on the reasoning `ContextOccupancy`'s standing caption was deleted for one commit earlier.

So the assertion is on the title. `— first-party` is now the whole of the card's provenance to a sighted reader, which makes shortening the heading to `Live from runs` the silent edit this file exists to fail, and the hazard the deleted footnote spelled out is on record in the component's module doc instead.

The shared-`LiveTelemetryTotals` case went in the same pass and has no replacement: the per-run table moved onto the top-row card and the band under it was deleted, so there is one rendering of the window on the page and "these two figures cannot disagree" has one party. A card that contains its own markup is not an assertion, and a test saying so would read as cover.

`Markdown.test.tsx`'s wikilink cases are the same bar reached from the knowledge page: a `[[link]]` the renderer does not recognise falls through as ordinary prose, and a vault's dangling links then read as none — on the page whose reason for existing is to find them. The 183 this quoted was counted with the resolver defect [knowledge-vault-and-graph.md](knowledge-vault-and-graph.md) records; the operator's vault had one on 2026-09-27.

So both signs are pinned, a resolved link *and* an unresolved one, along with the third answer that is neither: a target that exists and is not a note, which marked broken would report a healthy vault as a broken one.

The parsing cases sit beside them because each way of misreading a link is silent — a `|label` swallowed into the target breaks a link that resolves, an alias read as a heading points at a note that exists — and two cases pin what must *not* become a link, since the vault's own notes quote wikilinks inside code spans and fences while writing about them.

The last pair is the emphasis rescan: a bolded wikilink reached `<strong>` as literal text until the inner text was scanned again, and the second half pins that a caller with no vault behind it renders byte-for-byte what it did before, because every caller that predates the resolver prop is a model's report rather than a note.

The Obsidian block below them is one argument repeated per construct, and the argument is the measurement in `docs/verification.md`: 760 of the real vault's 785 notes carry a callout, 621 a table and 524 a task list, and a construct this renderer does not know does not error — it arrives on the page as the punctuation the author typed, which is what "the notes are not rendered" turned out to mean.

So each case pins the marker being *consumed* rather than the box being pretty: a callout that stays `[!warning]`, a table that stays a row of pipes, a checklist that stays `[ ]`.

Three of them go further than that because the failure is a wrong reading rather than an unrendered one — a callout's tone is its meaning and a danger drawn in the note colour is a warning the reader does not get; a `- [x]` drawn unchecked inverts what the note says; and a table's stacked `label` is a second copy of the head, so handing it the raw string put markdown on the phone in a table that read correctly on the desktop, which is a bug no desktop screenshot can contain.

Two more are the same shape as the wikilink pair, gating on the resolver: a `#tag` is a chip in a note and a word in a report, and a footnote reference with no definition behind it stays literal for the reason a dangling wikilink is marked rather than linked.

A third gate has a test of its own because it is the only invariant here that a *caller* can break from outside: a nested disclosure is on this app's never-used list, `RunOutput` renders every earlier cycle's report inside a `Disclosure`, and a model writing Obsidian's `> [!note]-` into a report would therefore build one from the inside — so folding is refused without a vault and refused again inside a callout's own body, and the case pins both rungs along with the fact that a refusal renders the text *open* rather than dropping it.

The three parser cases that are not about a construct at all — a pipe that is not a table, an escaped marker, an underscore inside a word — are there because each one *adds* meaning to text that had none, and a heading silently turned into a one-column grid or an identifier turned into italics is content this changed rather than content it failed to draw.

`Table`'s `stack` takes the column heads off the screen below `md` and makes the grid one block per record, so the only thing naming a value there is the `label` its own `Td` carries and the only thing carrying the row and column relationships is the explicit ARIA role — `display: block` strips the implicit one in every engine.

Drop either and the desktop is pixel-identical and the phone is a column of unnamed figures, or a stack of anonymous boxes to a screen reader.

The other direction is the promise the change was made under: a table that did not ask to stack must emit exactly what it emitted before, and since every mobile rule here is behind a breakpoint prefix, "no `md:` anywhere in a flat table" is the whole of that claim in one assertion — which is also the only form of it that can be checked without a browser.

The wrapper around a labelled value is pinned for the same reason from the other side: it is `md:contents` so it generates no box in the flat table, and a plain `block` there would be a silent desktop change in every one of the twenty-two tables that now stack.

Its last case is why `stack` is a *context* rather than a prop, and it is the one thing the widened coverage rests on: the workflow instance page draws two tables out of one `RunTableHead` and one `RunRows`, so a shared body that had to be told would be told at one call site and forgotten at the other — and the table that was not told would render its figures unnamed below the breakpoint, on a page whose desktop is unchanged either way.

Its control is half of it, for `dataDirClaim.test.ts`'s reason: the same body inside a table that did *not* ask must come back with no `md:` rule at all, or what is being pinned is a context that leaks rather than one that carries.

`Disclosure` exists because a hit target is invisible from every file that has one, and its ARIA fails the other way: a `role` or an `aria-expanded` on a native `<details>` is redundant in one engine and wrong in another, and the reader who finds out is using a screen reader rather than editing this file.

`LimitField` is the one control in the kit that can express "no limit at all", and a picker whose two options are the wrong way round throws nothing, typechecks, looks right on the page and starts an uncapped unattended run.

`ListView` is three boxes that look like one box with two typos in it: the capped one must release both halves of its cap below the breakpoint, where a 320px scroller inside a scrolling pane is a trap with no way past a list but through it, and the plain one must not become a scroll container, which would pin the runs list's sticky header to a box that never scrolls — every difference between the three is invisible on a desktop.

`ui/AsciiFrame.test.tsx` and `ui/AsciiBar.test.tsx` are the ascii skin's two, and they are the class of failure every instrument in this repository is blind to. The skin draws its chrome twice — once as a shape and once as characters, with `globals.css` turning one off — so **both** halves are in the DOM of every page under **both** skins, and the CSS hiding one of them is not what keeps it quiet. A card's frame is 1,600 characters; a reader that reached one is read "box drawings light horizontal" four hundred times before the heading it asked for, on a page that is pixel-identical, typechecks, and passes `smoke-pages`, which asserts a 200 and no sideways scroll and cannot see an accessible name at all. So what is pinned is the *text a reader is left with* once every `aria-hidden` subtree is dropped whole, and it is pinned at the root rather than node by node: hiding a frame's fills individually passes the same assertion and leaves a second frame added later announcing itself. The pair cases beside it are the same rule at the three marks that carry it — a status mark whose word is already on the row, and a `Switch` whose `[x]` would become the control's own accessible name and stop a `ListRow`'s label being read. `AsciiFrame.test.tsx` carries a **second** rule, and it is geometry rather than ARIA: the skin corrects this frame's inset for a host still carrying the border `uf-unboxed` only paints out, through a selector whose two halves are written in two other files, so renaming either class or wrapping the frame so it is no longer the host's own child leaves the rule matching nothing — and nothing throws, nothing fails to typecheck, the page renders, and every framed box in the app quietly draws its edge a pixel inside itself again. It is pinned by reading the selector **out of `globals.css`** and decomposing it against a rendered `Card`, never by restating either end, because an assertion that spells the class again passes whichever file moved. That construction is `deployment.test.ts`'s `assertReferencesResolve` one pair of files over, and the grounds are `docs/verification.md`'s: the same pixel has shipped app-wide twice, each time caught only by reading device columns off a screenshot by hand.

`AsciiBar`'s own grounds are arithmetic rather than ARIA, and they are `Meter.test.tsx`'s argument in a second unit. A fraction becomes a whole number of cells, and every way of rounding it wrong draws a plausible bar beside a figure that goes on being correct — so the only reader who catches it is one who counted the blocks. Three are pinned, each a reading an operator acts on: a window that has been used drawing empty, because 0.4% of twenty cells rounds to none; a window with headroom drawing full at the moment someone is deciding whether to start another run, because 99.6% rounds to all of them; and a ceiling that does not exist rounding to *something*, which is the invariant `Meter.test.tsx` already holds in pixels and which `DEFAULTS` deliberately leaves unset. The band is pinned in both directions for the reason `Meter`'s own is — it is the only thing on screen accounting for a guard that refuses a run above the visible bar, so it may not round away, and it may not appear where the head could not spell it. The last case is the pair again from the meter's end: every block character a meter draws sits inside one hidden span, and the percentage beside it is still text and still the value the widget reports. `fittedCells` earns its three on the same grounds one measurement over: it decides a *width* rather than a reading, and a count one too high draws a bar that hangs out of its card, which `.uf-meter`'s `contain: inline-size` keeps from widening the column — so nothing moves, nothing throws, and the page is pixel-identical to one that fits. It is a floor and not a round, because the count that fits is not the count that is nearest; it holds a readable minimum rather than collapsing a narrow box to `[]`; and it answers `null` for a box that was never laid out, which is every meter under the default skin, where the bar is `display: none` and measures zero. The case that names the reason the function exists at all is the pair at two advances: the same 300px box fits 22 cells where a cell is an em and 36 where the reader's face covers the block range at the monospace advance, which is the 2026-09-11 handoff's own bar and not a hypothetical.
