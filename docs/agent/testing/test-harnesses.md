# Test harnesses: which tests open a database, and how this page is checked

[← testing index](../testing.md)

Read before adding a test file that opens the database, points `DATA_DIR` or `CLAUDE_HOME` anywhere, or changes what `docClaims.test.ts` checks.

Thirty-eight are neither a function nor a rendering, and each earns it its own way: the twenty below, `deployment.test.ts` and `backupRestore.test.ts` after them, and the sixteen newer ones further down, which are the fifteen introduced as a group after `backupRestore.test.ts` and `docClaims.test.ts` near the end of this file.

That recipe is not this list's property and never was: `grep -rl 'process.env.DATA_DIR' --include='*.test.ts' --include='*.test.tsx' src | wc -l` answers **80** as this is written, 2026-09-29 — twelve more than open it — because `config.ts` reads the variable once at import and *any* file whose module graph reaches it — including the ones that only want a pure function out of a module that statically imports `db.ts` — must name a throwaway directory first or bind itself to the repository's own `.data`, which on a developer's machine is the real one.

Take the count from that command rather than from this sentence, and take the recipe from any of the files it names.

Each is its own file rather than a case in the pure suite beside it because `node --test` gives each file its own process and the harnesses want opposite things: `chat.test.ts` replaces `spawn` module-wide so it can count children and `mergeQueue.test.ts` must never bind `DATA_DIR` to the repository's own `.data`, where these thirty-three need the real database, the real `writeFileSync` failure, a real git repository and, for three of them, a real child that outlives the call.

`bootBlocks.test.ts` is not a case in `haltedMembers.test.ts` for a further reason of its own — both reconcilers it calls act on *every* row in the database, so they would close that file's fixtures out from under it.

`fleet.test.ts` is separate for that same reason turned up one further: `stopFleet` acts on every live row *and* every started instance, so it would take down any other file's fixtures mid-test.

The nine files that gained cases gained them for what the changes could break quietly. `budget.test.ts` pins that an unreadable window no longer disables the guards below it and that the documented order still decides which refusal is *named*. `windows.test.ts` pins a model-scoped wall standing on its own with `planFraction` still null, that a projection past its own window's reset is dropped rather than clamped and that a trailing 7-day window keeps its projection for want of a reset to drop it at, that the counterfactual's buckets still add up to the window, that `byTool` is empty for a caller that supplies none, and that the session carries the provider's reading forward on **its own** post-fetch spend rather than the week's — the two windows are anchored independently, so a block open across a weekly rollover holds turns newer than the fetch and older than the week, and summing the residue from the week slice while the total comes from the block leaves `atFetch` describing neither window; And `src/app/api/settings/route.test.ts` gains three probe rows rather than cases, the typed table making a new `Settings` key a compile error there until it is probed — one of them asserting a *clamp*, since a read cap at or past what the CLI itself refuses is a switch that reads as on and does nothing.

`docClaims.test.ts` is the completeness claims in `CLAUDE.md` and in `docs/agent/` held against the code they are about, and it earns its place on `deployment.test.ts`' grounds one layer up: an agreement between two files that nothing else reads, whose failure is silent and whose reader is the next agent editing `src/lib/`. `CLAUDE.md` routes that editor to one of these documents *before* they touch the code, and the documents answer with counts and with enumerations — "there are 34 tables", "closed at ten", "all five", "the whole of that class". Such a claim decays the moment somebody adds the thing it did not count: nothing throws, nothing fails to typecheck, and the sentence still reads as authoritative, which is worse than no sentence, because a list that says of itself that it is complete is the shape that makes a reader stop looking.

It has been paid by hand instead, one issue at a time — #123, #124, #133, #136, #140, #150, #151, #153, #161, #162, #163, #166, #169, #174, #175 and #176 are each one count, one enumeration or one name corrected by a person, and #144, #152 and #154 are indexes of sweeps for more. Three were checked against the tree when this file was written and two had drifted again: #161's table list, closed at "says 22, `migrate()` creates 24", stood at 34, and #166's globalThis grep, closed at "it misses two live keys", missed five.

**Every number it asserts is read out of the document.** Nothing in it hard-codes 34, or ten, or five — each case lifts the claim from the prose and compares it against a measurement of the tree, so the only way to clear a failure is to correct the sentence a reader will act on, and the message says exactly that. A reworded claim fails loudly rather than passing vacuously, which is the one way the whole file could go quiet while everything it names rots. The claims it pins are named in its own docblock, and what it deliberately leaves alone is the larger half: a claim about intent, or about *kinds* rather than counts, cannot be measured, and a reading that carries its own date — `# 147 as this is written`, above — does not decay and needs no pin. Adding a case is a decision about one claim, not a pattern to run over the prose.

**`docs/verification.md`'s per-area table is the one claim it pins outside `CLAUDE.md` and `docs/agent/`, and it earns that on its drift rather than on routing.** The table gives each `docs/verification/*.md` file's *Verified* and *Not yet verified by hand* counts and a Total, and every entry filed is a hand edit to one row and to the Total that nothing checked: bca9673 found five rows and the Total behind their files, and e6ed6a1, sixteen minutes later, moved a row and left the Total one short. `CLAUDE.md` requires each *Not yet verified by hand* list to stay honest, and these figures are how a reader decides which of those lists to open and how much is still unmeasured; a wrong one reads exactly like a right one. So the case reads each row's two numbers and the Total out of the table, counts the entries under each linked file's two sections — a top-level `- **` bullet or a paragraph that opens in bold, the convention every file is written in — and fails on a file with no row, on a row that disagrees with its file, and on a Total that is not the sum of its rows. An entry written in some other shape is undercounted and fails the row that counted it; a section holding nothing but such entries would count zero, so a section may be empty only by saying "None yet.".
