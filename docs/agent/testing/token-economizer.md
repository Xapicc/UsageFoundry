# TokenEconomizer: availability, env pins and the catalogue refresh

[← testing index](../testing.md)

Read before adding or editing tests of `tokenEconomizerEnv`, `tokenEconomizerFor`, the `tokenEconomizerDir` case of `buildArgs`, or the TokenEconomizer group in `deployment.test.ts`.

`tokenEconomizer.test.ts` earns its place on the grounds that both of its failures are silent and one costs money. `tokenEconomizerEnv` must name **every** mechanism, an `off` one included: a mechanism left out of the environment falls through to the plugin's config files, which any work cycle can write, and then to the plugin's own default — `nudge` for the loop guard, whose judge is a billed `claude -p` that writes no transcript and so reaches no meter here. The case asserts the shipped defaults land as `auto`/`off`/`off`, not just that the keys exist. A second pins that this app's micro-skills `on` is spelled out as `envfacts+distiller` rather than passed as the plugin's own word, so the switch cannot change meaning when the plugin's idea of `on` does, with `envfacts` passed through as itself as the control. A third pins the interpreter (`/usr/bin/python3`, because the agent `PATH` puts an agent-writable directory first and the launcher runs the first `python3` it finds), the state root and `TE_MODE=headless`. `tokenEconomizerFor` has three: nothing loads while the switch is off whatever the modes say; a Codex or local cycle loads nothing, which no argv rule would otherwise stop since a local cycle is spawned through Claude Code and the plugin's judge would ask the local server for `haiku`; and an absent plugin directory answers `unavailable` rather than `ready`, asserted against what is on disk so the case holds on a host and in the image. `ensureTokenEconomizerCatalog` is not tested: it spawns the CLI, and its failure mode is a line in the operations log, which is the behaviour it promises.

The `buildArgs` case in `orchestrator.test.ts` pins that the plugin directory rides the same `--plugin-dir` flag on a resumed cycle too, and is absent for `undefined` and `null` — `--plugin-dir` does not survive `--resume`, so a cycle that lost it would run without the hooks and look ordinary.

The TokenEconomizer group in `deployment.test.ts` reads text, because there is no Docker here, and pins the agreements between four files that fail with nothing throwing: the path `tokenEconomizer.ts` hands the CLI is the directory the Dockerfile fetches into; `TOKENECONOMIZER_REF` defaults to a full commit sha; compose passes it with `${VAR-default}` rather than `${VAR:-default}` so that an empty value in `.env` can switch the bundling off; and the state directory is a named volume whose mount point the Dockerfile's `mkdir` creates, so a fresh volume takes `node`'s ownership instead of root's and the hooks, which fail to persist silently, can write it.
