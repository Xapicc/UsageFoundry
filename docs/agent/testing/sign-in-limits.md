# Sign-in limits

[← testing index](../testing.md)

Read before adding or editing tests of `loginLimiter.ts`, `loginAttempts.ts`, `bearerLimiter.ts`, `middleware.ts`'s bearer branch, or any case that sends more than one wrong token: the budgets on the master token and what charges them.

`loginLimiter`'s two (`loginLimiter.test.ts`) fail in opposite directions, one that never fires being bit-for-bit the unbounded route and one that never lets go locking the operator out of an app whose only other credential is an environment variable and a restart.

`src/app/api/login/route.test.ts` carries the limiter's *concurrent* half, because the pure decision cannot see it: `planLoginAttempt` was right all along, and the route asked it and charged the answer on opposite sides of `await req.json()`, so a burst passed the check whole and the budgets bounded only a client that waited for each answer. Two bursts pin it — one source sending three times its budget at once, and rotating sources sending more than twice the install-wide budget, twice, with `Date.now` wound past the global lockout between them — and each asserts the *exact* split between 401 and 429 rather than an upper bound, since a limiter that refused the whole burst would pass a bound while locking the operator out early. Every answer's body is read and compared, because the oracle rule is that a locked answer and a wrong one look the same. The cases clear `login_attempts` behind them: a global lock left standing refuses every later case in the file, and the wound clock leaves one that outlives the real minute.

The same file pins what a request carrying no forwarding header is charged to, in both directions, because each failure is silent in its own way. Ten headerless wrong guesses followed by the right token, also headerless, must be a 200: one shared bucket for every unnamed client locked the operator out on anybody's ten guesses, and nothing anywhere said whose they were. And a headerless burst past the install-wide budget must still be compared exactly that many times — the case that stops "held to no bucket of its own" from becoming "held to no budget at all", which would be the unbounded route again for the one client compose ships with.

It also pins what a refusal may write, since `/api/login` is exempt from the edge gate and answers anybody. One authenticated row is seeded, twenty thousand and ten wrong tokens are sent from one address — ten 401s and the rest 429s — and the row must survive with nothing beside it, while every refusal leaves exactly one `login.refused` line on stdout naming the address and not the guess. The absence is the half nothing else would catch: a refusal written into `request_log` evicts its oldest row, and this is the route an anonymous caller can drive. The row count is asserted rather than the rows `deepEqual`-compared, because on the unfixed route that assertion's diff of twenty thousand rows against one took the container past its memory limit. A second case pins the half the table still wants: a sign-in that succeeds writes its row.

`src/middleware.test.ts` pins the gate's bearer branch as a guess at the same secret, because an unbounded gate is bit-for-bit a bounded one until somebody counts — and it was unbounded, answering a wrong bearer 401 and letting the right one through on every route while sign-in sat locked. Two thousand concurrent wrong bearers must be compared exactly the install-wide budget's worth of times, every body read; inside the lock the right token must get the wrong token's status, `Retry-After` and body, and a page path the sign-in redirect; the lock must lift once its minute has passed. A session cookie must still open the gate while bearers are locked, since the cookie is checked first and a lock anybody can trip must not reach the operator's browser. And a right bearer must not refill the budget — the decision that differs from sign-in's, pinned because a script polling with the real token would otherwise clear the count between every pair of guesses and nothing would look wrong. The file replaces `Date.now` for its whole length rather than per case, because the budget is module state and only time clears it: each case starts by winding past whatever the one before it left standing. It calls `middleware()` in plain Node, so whether that state survives between requests in the edge sandbox is a hand check in `docs/verification/security-and-sandboxing-sign-in-and-bearer.md`, not something this file can show.

The two exempt paths that compare the master token themselves carry the same case beside their other tests. `src/app/api/status/route.test.ts` sends wrong master bearers until sign-in's install-wide bucket locks, and then asserts that the master token is refused like a wrong one while `UF_STATUS_TOKEN` still reads the page — the second half because a lock any caller can trip must not blind the monitor, and the first half's charge is asserted on the failure count, with a right master bearer charging nothing. `src/app/api/login/route.test.ts` does the same to `/api/logout`'s `all` branch, where the right token inside the lock must answer 401 **and revoke nothing**.
