# Run page panels: background tasks, touched files and conflict maps

[← testing index](../testing.md)

Read before adding or editing tests of `runTasks.ts`, `runTouches.ts`, and the touched and conflicts maps (`touchedMap`, `touchReplay`, `conflictMap`).

`runTasks.test.ts` is the reducer behind the run page's background-task panel, and it earns its place on `cycles.test.ts`'s grounds — a pure function deriving a claim from an event stream, where every way of being wrong renders as a panel that is working.

**The case that carries the file is that leaving a `background_tasks_changed` snapshot is not an ending.** That event is a list of what is still live, so a task that finishes *drops out of it*, and the obvious reading — absent from the latest snapshot, therefore done — marks a healthy task finished the moment the next one starts, on a panel whose entire claim is that it reports what the events said. Nothing throws and the row is plausible, which is why the assertion is on the state and on `endedAt` together rather than on the count of rows.

The opposite failure is pinned beside it: a terminal `task_notification` is terminal whenever it arrives, so a replay that delivers a `task_started` or a stale patch after it cannot put a finished task back on the live list — the reconnect case, since the page replays from the last event it saw and duplicates are routine rather than exotic. The status word is asserted in both orderings for the same reason, because arrival order deciding an outcome is invisible in any single run.

The rest are the honest-unknown ones. A snapshot-only task keeps `startedAt` null rather than borrowing the snapshot's own timestamp, since a duration measured from when the browser joined is a smaller number than the truth presented in the place a measured one goes; a status word this app has not read is terminal *and* keeps the CLI's word, because mapping it onto `completed` claims an outcome and leaving it running claims a live shell on a run that is over; and an in-flight word must not end a task while an `end_time` alone must, which is the pair that keeps the open-set `patch` from being read as a closed one.

`task_progress` is asserted to open **no** row, and that is a scope boundary rather than a shape check: every instance in this install's transcripts carries `subagent_type`, `usage` and `last_tool_name` and carries no `task_type` and no `status` — it is a sub-agent delegation's progress, which has its own event kind and its own label in the log, and one word covering both is the confusion the panel is scoped away from.

`runTouches.test.ts` covers the set difference and the merge behind the Files tab's reconciliation, on the same grounds one line up and with a sharper edge: this one produces a *sentence an operator acts on*. "This run changed a file it never opened" sends somebody to read a diff hunk nothing wrote, and a group taking the wrong side of the difference says exactly that with no error anywhere. The merge is the other half — the scan groups by tool and by caller as well as by path, so an isolated run that reached one file through both `work_dir` and `folder` arrives as two rows, and failing to fold them shows one file twice with its counts split, which reads as a run that read something half as often as it did. `distinctTouched` is asserted rather than left implied because it is not decoration: it is one of the two figures the tab exists to print, and the next decision about drawing any of this is made from it. The fallbacks are pinned too, each because the wrong one is silently plausible — a tool this build has never heard of counts as a *read*, so being wrong understates one column and leaves the group membership alone; a delegated call whose `Task` was never seen is `delegated` rather than `main`, since "some sub-agent" is true where "the main thread" is not; a file the main thread read and a sub-agent edited lists both callers, because showing one would make the other disappear; and a group with no counts at all sorts by path, or `changedNotTouched` would come out in whatever order the diff happened to list, which differs between two reads of the same run. `scanTouches` is deliberately not covered, and neither is `scanTouchSequence` beside it: they are queries, there is no fixture database here, and what a test of either would assert is SQLite's behaviour rather than this app's. What the second one turns into is covered — `touchReplay.test.ts`, two paragraphs down — and what it *was* measured at is in `docs/verification.md`, where a seeded run answered 399 touches over 48 distinct files against a built app.

`touchedMap.test.ts` covers the three things on the map at `/runs/[id]/touched` that have a decidable answer, and nothing about the drawing. The reduction from those four groups to a directory tree is first because it is the picture's whole claim: a path filed under the wrong parent puts `src/lib/db.ts` in a cluster labelled `docs`, and what an operator then reads is a repository that does not exist — so the ancestor sums are asserted all the way up (a folded `src` that counted only its own direct files understates what it stands for, and prints the smaller number just as confidently), depth is asserted against a deep file arriving *before* a shallow one, and the two roots are kept apart because collapsing them files `/etc/hosts` under the repository root. The fold is second, and one assertion runs under every case of it: drawn plus folded equals the total, because a picture's missing node is not a missing row anybody notices. That it folds the *deepest* directory rather than the largest is pinned by name — largest-first is what reusing `capGraph` would give, and it takes `src`, which is the directory the run worked in — as is a root never folding, an over-budget depth 0 drawing everything rather than dropping any of it, and an expansion carrying its ancestors, without which the next plan closes a parent over the top of the click and the click reads as having done nothing. The three ways of having nothing are third, and they are the same three the table keeps apart for the same reason: they render as an empty canvas instead of an empty list, and an empty canvas reads as a run that touched no file. `swept` is asserted to outrank a diff that loaded, since a checkout is kept on a different clock and drawing changes without saying the events are gone is a map claiming the run read nothing; an absent diff is asserted to leave every node unmarked, because the changed set is then unknown rather than empty. The rendering is not faked into looking tested — there is no DOM here, an assertion over a radius or a colour would restate the code, and `canvasView.test.ts` already holds the arithmetic that draws a plausible wrong picture without saying so.

`touchReplay.test.ts` covers where the playhead on that same map is standing, which is the only thing about the replay an eye actually reads, and it is on `touchedMap.test.ts`' grounds one paragraph up rather than on new ones: every way of being wrong here draws a plausible picture of a run that did not happen. A step placed on the wrong node walks an operator through an order the run never worked in. A step placed on **nothing** is what a touch behind a fold gets without the ancestor walk in `placeTouches`, and the mark then disappears for as many frames as that file was read — which reads as the run pausing rather than as a directory the map rolled up, and quietly breaks the one promise this surface makes out loud. So the fold case is asserted both ways: shut, every touch behind it lands on the fold and none lands on null; opened, the same index resolves to the file itself, which is the whole of what makes clicking a directory mid-replay do anything, since `position` is an index into the sequence and no fold changes it. The plan under those assertions is built through `reconcileTouches` and `planTouchedMap` rather than hand-assembled, because a fixture that happened to hold every path would pass while the real map folded half of them. Rest is asserted as `dimmed === null` and not as an empty set: null is "nothing is narrowed" and is what keeps the map at position 0 pixel-identical to the one an operator who never touched the scrubber sees, where an empty set is "narrowed to nothing" and would be the replay replacing the view it is supposed to ride over. Accumulation is asserted on a file read twice, since the step is one **call** and not one distinct file and a count that deduplicated would make the busiest file in a run indistinguishable from one read once; a file the main thread and a sub-agent both touched is asserted to stay one node across two positions, because splitting by actor would draw one file as two places in the repository. `changedNotTouched` is asserted to be dimmed for the whole replay and never reached — it has no event and so no position, and counting it as reached at 0 would say the branch changed it *because* the run touched it, which is the reconciliation asserting the thing it exists to check. Directory anchors are asserted never to dim, a position past the end to clamp onto the last touch rather than off it, and an empty sequence to answer rest rather than a frame that dims the whole map on its way to having no step in it. The control is not tested, for the reason the paragraph above gives about the canvas: a `requestAnimationFrame` loop has no clock in this runner and an assertion over a disabled attribute would restate the component.

`conflictMap.test.ts` covers the same three things for the map at `/runs/[id]/conflicts`, and a fourth that is narrower than any of them. The reduction earns its place on `touchedMap.test.ts`' grounds one paragraph up, with one field carrying the whole feature: `regionsRead: false` has to survive as `clashes: null` and never as a zero. `land.ts` opens the merged content of only the first `MAX_CONTENT_FILES` of a preview, so a large conflict arrives with a complete path list and a clash count for ten of them — and a `modify/delete` that *was* opened really does hold zero regions, which is why the two cannot share a number. Summed as zero, a directory states a total the preview never had, and there is nothing on a canvas that would contradict it; so `subtreeClashes` is asserted over a read zero and an unread null together, with `subtreeUnread` counted apart, which is what lets the surface say the total is a floor. The fold is asserted for one thing only — drawn plus folded equals the total — because every other rule it obeys is `pathMap.ts`'s and is pinned over there rather than restated through a second binding. The ways of having no conflict are third and there are seven of them: `already-merged`, `fast-forward` and `clean` are three different true statements about three different branches; `unknown` is git declining to answer and is asserted never to become one of them; a run with no branch and a branch that is gone are two more; and a `conflict` naming **no** file is the seventh, which must not be drawn at all, since a canvas with nothing on it is exactly what a clean merge looks like. `gone` is asserted to outrank the preview for `swept`'s reason on the touch map: `landState` returns before it previews anything when the branch has gone, so the preview it still carries is the `"Not checked."` placeholder, and read in outcome order first a deleted branch renders as "git could not work the merge out" — true of nothing, and it buries the sentence that says where the work went. The fourth thing is `clashKindOf`, and it is the narrowest test on this page: git's `-z` informational record spells a content conflict `contents` in its *type* field and `content` only in its human message, verified against `merge-tree --write-tree -z` on 2.39.5, which is what the container ships. A classifier written from the message puts every ordinary conflict in the "some other kind" bucket, on a map where nothing would look broken. A type git gave nothing for is pinned as its own case in the same breath, because `parseMergeTree` parses that section defensively on purpose and rendering its silence as the commonest kind would be this map inventing the annotation the parser declined to guess. The drawing is not tested, for the reason one paragraph up.
