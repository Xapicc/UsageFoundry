`plugins.ts`'s two (`plugins.test.ts`) decide what code every agent loads, and a bare `--plugin-dir` with no value takes the *next* argv entry as its path — which in `buildArgs` is a permission mode nobody chose.

`plugins.test.ts` also drives the switch against a scratch mount and database, on the same grounds one step earlier: an enabled plugin whose folder went or whose manifest broke could not be switched off, because switching off ran the enable proofs, and it stayed stored — a broken one still reaching every cycle's `--plugin-dir`, a vanished one waiting for whatever was next written to its path. Nothing about either looks different from a plugin left on deliberately. The cases pin that off succeeds in both states and leaves nothing stored, that a broken manifest is withheld from spawns, that every enabled entry the list has no row for is a problem carrying its switch-off, and that switching on still refuses both containment escapes and a broken manifest.

`buildArgs`'s two argv cases in `orchestrator.test.ts` join the `--plugin-dir` one on the same grounds and against the same silence. The first is now the **inverse** of what it used to assert: `--autocompact` must *not* be emitted, because `contextPruning.ts` owns the ceiling and both mechanisms running would have the CLI summarise a conversation moments before this app ended the cycle to prune it — the prune measuring what the summariser had already discarded, and the run paying for both. A reinstated flag fails nothing and looks like an ordinary cycle, which is the same silence the old direction was pinned against. The second is unchanged: a second `--append-system-prompt` is a replacement rather than an addition, so the delegation notice and the process-safety notice have to travel under one flag or one of them silently does not arrive, and the half that goes missing decides either what a run costs or whether it has been told why `pkill` is denied.

`buildArgs` gained three argv cases beside its `--plugin-dir` ones, on the same grounds and against the same silence: that the skill directory and the vault's `--add-dir` reach the child, that both survive `--resume` — which restores neither — and that neither appears when the switch is off.

The taskboard's argv earns three more, and its failure is the same silence one notch quieter: an MCP config the CLI was not handed is a child with **no tools**, which reads from a transcript exactly like a model that chose not to call any, so nothing anywhere reports it and the run finishes looking ordinary having closed nothing. The first asserts `--mcp-config` rides a **resumed** cycle as well as the opening one — the version that passes it once gives every run a board that works on cycle one and vanishes on cycle two. The second asserts `--strict-mcp-config` is never there, and it is pinned rather than commented because the two argv builders read alike and this is the line between them: strict on a run strips the operator's own MCP servers out of every cycle, which is invisible from inside this app and which they would read as their servers having broken. The third pins the notice to the flag in **both** directions — a run with the board is told the three tool names, and a run without it gets an appended prompt byte-identical to the one this app sent before the feature — because a run told to call tools it does not have and a run holding tools nobody told it about are the two failures that pairing exists to make impossible, and both look like a normal run from the outside. `--mcp-config` is also on the widest argv `injectionFates` classifies, so a row for it is a test rather than a note.

The self-hosting notice gained one assertion beside the `PROCESS_KILLERS` one it belongs with: that it contains no multi-digit literal, because `--append-system-prompt` puts the notice on every sibling's command line and the worked example it used to carry — `pgrep -f 3100` — matched them all, twice, in production.

That flag is five notices now and the assertion is two, because the last of them is a price list whose every line ends in a figure: the spawn under test carries one, rendered by the real generator rather than spelled out, the strict form is scoped to whatever the flag holds *without* it — derived, so a sixth notice inherits it unnamed — and the price list is held to the other half of the same rule, that nothing beside a figure reads as a command.

The split earns its place rather than the fixture merely growing a field: asserted against a spawn with no price list, as it was, the strict form was a test that passed on every input except the one it could not be given.

`fileCostNotice.test.ts` pins the two ways that feature is worse than not shipping it, and neither shows up in a typecheck, a smoke test or a run's log. **Drift is the expensive one**: the text joins the cached prefix, so a generator carrying an order-dependence or a clock would cold-start every token behind it on the next cycle of the same run — the run still works, it just costs several dollars a cycle more, for a notice worth a few cents — and freezing the column is only worth anything if what it freezes is deterministic. **Bloat is the quiet one**, since every character is re-read on every turn of every cycle, so a repository with very long paths has to cost a shorter list rather than a bigger prompt and a notice over its budget looks exactly like one under it. The rest is the degradations, because the alternative to a price list is not a broken run but last week's run: every failure has to land on `""` rather than on a half-built list or a throw at the one door every run comes through.
