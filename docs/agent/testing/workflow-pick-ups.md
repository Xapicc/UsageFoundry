# Workflow pick-ups

[← testing index](../testing.md)

Read before adding or editing tests of `pickUpsOf` or of a door it offers (`retryOrchestratorBlock`, `retryMergeBlock`, `retryDeliverBlock`, `leaveRunBehind`, `resumeLoop`) in `src/lib/workflows.ts`; the deliver one's cases are in [delivery.md](delivery.md).

`workflows.test.ts`' `orchestratorRetryRefusal` cases pin which failed deciding turns the pick-up may run again, and both wrong answers are silent. Offered for a block that had decided, the retry is a second turn deciding the same runs over a first whose specs are still stored — reachable only after a restart, which writes a `thinking` block `failed` without settling it. Refused for one that had not, the only way past a turn that failed for want of a signed-in provider is a fresh Run, which repeats every block that already finished. The cases are the nothing-decided turn, the count in the sentence (singular and plural, because the operator reads it to decide whether to run the workflow again), `started` above zero with no specs, and each of the four other statuses named in the refusal the route returns. The empty-list decision is not a case here: it is `emitted: 0` and so the same input as the first, and what makes it different is a column the DB file below reads.

`orchestratorPickUp.test.ts` opens the database, because what is left over is the writes the pure decision cannot reach, each of which is silent. It is its own file for `fleet.test.ts`' reason — `advanceInstances` walks every instance in the database, so a retried turn left running would be claimed against another file's fixtures — and it waits for the turn it starts to end against a `claude` that is not there rather than halting it, since a halted turn's tail still reads the database after its awaits and the file closes it when its last case returns. The retry case asserts the claim, which is the evidence the turn was started through `startBlockTurn`, the only place a cap or the instance budget is asked, and that the failed turn's four cost columns are untouched: a column reset on the way back to `waiting` reports the block cheaper than it was, and the instance guard compares its limit against that sum. The empty-decision case asserts `emitted_specs` is NULL straight after the call, before the new turn could have written anything, and was confirmed to fail with that one clause removed from the UPDATE: `[]` is a set column, `emitBlockRuns` refuses a second call on any set column, and the operator would pay for a turn that is refused at everything it decides. The refusal cases assert that nothing was written — a block with stored specs keeps them, and a block whose successor has started stays `failed` — and the halted case is the instance-level rule, `reviveBlockedDependents`', that a pick-up is never a way back through a halt.

`orchestratorTurnRetry.test.ts` is the automatic counterpart: a deciding turn that failed is started again inside the press of Run, up to the block's `turnRetries`. The decision, `blockTurnRetries`, is pure and sits in `workflows.test.ts` beside `blockSettlement`, including a case that asks both about the same inputs, since a turn one calls `emitted` and the other restarts would be decided over and carried out at once. This file spawns real children against a stub `claude` whose outcome per invocation (`ok`, `fail`, `die`, `hang`) is read from a plan file, and counts the invocations, because a second child having been started or not is the only evidence of what a retry did and every wrong answer is silent: a retry that skips `startBlockTurn` skips the instance budget, a retry that does not bank the failed attempt makes the block and the instance total cheaper than they were, and a halt's dying child read as a failed turn buys a second child for a workflow the operator stopped. The cases are the retry that succeeds with both attempts' cost on one row, the block that saved none (set to 0 and absent alike), the limit holding when the retry fails too, a turn that died without a `result` banked as unreported next to one that reported, an operator's stop, the instance budget tripped by the first attempt's own cost with a control under a limit that has room, a refusal by this app with a control that retries without one, and the stored empty decision cleared before the new turn can emit. The stop case also asserts the notes do not say an attempt was about to start, because the instance being closed and the child being gone each stop a second spawn on their own and only the decision itself keeps the record honest; it, the budget case and the refusal case were each confirmed to fail with their one clause removed from the compiled output. It is its own file for `orchestratorPickUp.test.ts`' reason.

`loopSection.test.ts` has one more case for it, beside its failed-merge retry and in the same describe: a pass whose first member is a deciding turn that fails. It asserts the one thing neither file above can, which is the *list* inside a pass — the offer is the failed block alone, not the loop, because the loop's own pick-up would stop again on the same sentence — and then that the retry takes the pass back (the loop `looping`, the member `thinking` again) and carries it to a landing with the two turns' cost summed on the one row. It earns its place for the reason the merge case does: a pass member's id names no node of the graph, so a retry written against graph ids alone passes every case above and leaves a stopped loop stopped for ever.
