# The local provider

[← testing index](../testing.md)

Read before adding or editing tests of `localProvider.ts`, `localCertification.ts`, or the gate `landState` and `deliveryState` put in front of a local model's branch.

`localProvider.test.ts` pins `localCycleEnv`, the one place a local cycle stops being a Claude cycle, and both of its failures are silent in the worst direction. Leave `ANTHROPIC_BASE_URL` alone and the cycle goes through winnow's proxy to Anthropic, under a model id Anthropic does not have or — worse — on the operator's plan; leave an Anthropic credential in place, or leave `ANTHROPIC_AUTH_TOKEN` unset so the CLI falls back to the OAuth login, and the subscription credential is sent to whatever server the base URL names. Neither throws. So it asserts the base URL, the token, the config directory and all six model roles are set, that every credential and routing variable on `LOCAL_STRIPPED` is gone — including the OTLP ones, which would report a price the CLI made up — that the placeholder token is set when the server wants none, and that the Claude environment it was handed is not mutated. `parseLocalSignIn` earns cases on what it must refuse: a pasted `…/v1`, which is a 404 at the first cycle that names nothing; a credential in the URL, which the page would read back; and a model id that would not survive argv, a leading dash included. The context window earns two: blank is no window and a number is a whole number, and one under `MIN_LOCAL_CONTEXT_TOKENS` is refused, since the CLI would compact on every turn inside it — and `localCycleEnv` is asserted to set `CLAUDE_CODE_MAX_CONTEXT_TOKENS` only when the sign-in names one, because a window that never reaches the child is a run that compacts against 200,000 with nothing saying so. `probeLocalEndpoint` is pinned on the OpenAI-shaped 200 it must not accept, because that server answers a model list and fails every cycle.

`localCertification.test.ts` is the decision: the verdict parser on the hedges it must read as no verdict ("APPROVE with caveats", a verdict inline in another section, an echoed instruction above the real answer), the frontier predicate on a Haiku and an unplaced id, and `certificationRefusal` on every state an approval can be stale in — running, failed, no commit recorded, a rejection, no clear verdict, a non-frontier model, and above all a branch that moved after the review, which is the one a person is least likely to notice.

`localLandGate.test.ts` is `loopMergeOwnership.test.ts`' harness — a database, a real repository, `DATA_DIR` named before the first import — for the one question the unit file cannot ask: whether the decision is ever put. A `landState` reading the wrong review, the wrong tip, or a Deliver path that skipped the check would leave every unit case green and the button working. It writes the run and review rows the way the app does, commits on the branch, and asserts Land and Deliver refuse with no review, open on an approval of the tip, close again when the tip moves, stay closed on a rejection, hold a Claude run that shares a local run's branch, and ask nothing of a branch only Claude worked on.

`credential-audit.test.ts` covers `/api/local-provider` as a seventh credential route — see [auth-config-and-status-routes.md](auth-config-and-status-routes.md) — with a stub HTTP server as the endpoint, since the route probes before it saves.

`reviewBlock.test.ts` pins a workflow review block's decisions one step at a time — the same strict verdict, a fix round only while rounds are left, never one on a block with none, set aside after the last with the tasks marked, and a review that could not run, a fix the operator stopped, or a fix that failed before its first work cycle set aside *without* marking anything, because none is a judgement on the model — the last was marked until 2026-10-17, so a fix run refused for a signed-out local provider or an unmade worktree reopened its tasks needs-frontier and blamed the model. `statusVerdict`, the verdict a block takes from each run's status instead, is pinned beside them for every `RunStatus`: only `completed` approves, and every other ending — the live ones included, which no link should hand it — is set aside naming the status and never marked, since an approval there lands work that asked for review with nobody looking and a mark keeps a local pass off a task no model judged. `workflows.test.ts` carries what the scheduler hands on past one: the fix run the review approved rather than the attempt it rejected, an approved branch whose run asked for review, nothing — and a merge that still settles — when every branch was set aside, and a merge blocked behind a review block that failed; a run block behind a review block, whose planned dependency list is handed to `releasableRuns` and must release it behind an approved run that ended `completed` or `needs-review` — the second failed before `reviewVerdict` handed approved runs on under `on-finish`, written `blocked` by the creation path after the planner had called the link satisfied; and, in the same file, the save-time rules for `provider`, `fixRounds` and `verdictSource` — absent read as `model`, a value it cannot read refused rather than defaulted, and fix rounds or an `on-success` link into a status verdict refused by name — and the provider half of `planNode`. `canvasGraph.test.ts` has `worstCaseRuns` counting a review member's fix runs, and a review switched to a status verdict saving with its hidden fix rounds sent as 0 and counted as none. `commandVerdict`, the verdict a block takes from a verify command saved on it, is pinned in `reviewBlock.test.ts` for each way a command can end: only a pass that ran approves — `landVerdict`'s pass for a blank command never ran — and a non-zero exit, a signal, a timeout and a command that never ran are each set aside — the ending on the first line, the output's tail on the lines after, and a sentence when it printed nothing — never marked; `reviewBlockSummary` is pinned to name a branch by its note's first line. `workflows.test.ts` pins the command's save rules: kept as typed, every refusal `parseVerifyCommand` makes refused at the save in its words, a non-string refused, fix rounds refused, and a command beside another kind dropped unread. `canvasGraph.test.ts` has the draft sending the command only while that kind is picked, with fix rounds sent as 0 under it.

`reviewBlockRun.test.ts` is `localLandGate.test.ts`' harness with a stand-in for `claude` — a script that approves a brief carrying a marker and rejects the rest, printing the `stream-json` result a review ends with — for what no pure test can see: that the block, handed two branches, asks each for a verdict, records the tip it was shown, hands on only the approved one, lands the reviews' cost on its own row, and marks and comments the rejected branch's task. Every one of those fails silently, and the first as a merge of work nobody approved. It awaits the block through a ref'd deadline because the block polls its reviews on an unref'd timer, which is deliberate, and in the app the HTTP server keeps the loop alive. Awaited bare, the loop drained once the stub reviewers exited, and `node:test` cancelled the case on every run with every review already written. Its last suite hands a status-verdict block a completed run and one that asked for review: no reviewer may start, the block's cost stays 0, and the second run's held task stays claimed, unmarked and uncommented — a reviewer there is billed on a block saved to spend nothing, and a reopen moves a task nobody judged. It was checked failing with the status branch disabled. The suite after it is a command-verdict block over a fixture repository whose branches each commit their own `check.js`, run by one command in four runs' slots: the pass approved, the failure and a one-second timeout — `landGate.runVerify` replaced on the module object to pass a short `timeoutMs` through its real timer — set aside with their exact endings and tails, and a run with no checkout set aside with Land's refusal minus its Settings sentence; no reviewer started, nothing billed, the held task untouched. Each branch's own `check.js` deciding the outcome is what proves the command ran in each run's checkout rather than in the operator's tree or one shared slot. It was checked failing against the tree before the command verdict existed. Its next two cases pin the reused-slot rule (`isolation-and-landing/review-verify-command.md`). Three runs are recorded in one real `git worktree add`ed slot that stands on the last one's branch, and the slot holds an ignored `deps/marker.txt`: the holder is judged in place, the two before it with the slot switched to their branch, and the early branch whose check needs the marker is approved, so the ignored tree is what the check ran against and a freshly cut worktree would have failed it. `landGate.runVerify` is replaced on the module object to read, from inside the running command, which branch the slot stood on and whether `holdSlot` and `isSlotBorrowed` refused, and to try `reopenRun` on the slot's holder and a `createRun` continuing it — each of which would otherwise have switched the checkout under the command and passed it, because the tip comparison reads the branch's ref and not the tree. A slot holding an untracked file and one with an active run in it are set aside with their own sentences and left untouched. The second case holds the slot with `holdSlot`, as a land's check does, and asserts the branch is still `reviewing` after 300 ms and approved once the hold is released; against a block that set the branch aside on `busy` it fails by its assertion. Both were checked failing with `takenOverBy` returning null, and the first with `switchBack` and each of the `planWorkspace` and `reopenRun` guards disabled in turn, by editing `.test-build/lib/*.js`.
