# Stacks, the tool inventory and the end of the function list

[← testing index](../testing.md)

Read before adding or editing tests of `stacks.ts`, `scripts/apply-stacks.mjs` and `toolInventory.ts`, or of the functions at the end of the list of what `npm test` covers (`workspace.ts`, `cycles.ts`, `format.ts`, `jsonRequest.ts`, `canvasGraph.ts`, `unsavedWork.ts`, `logLine.ts` and the rest named there).

`toolInventory.ts`'s four (`toolInventory.test.ts`) are one page's claim about what an operator's agents can run, and every one of them is wrong quietly. `parseToolList` splits two variables whose separator rules deliberately differ — a comma separates `UF_GH_EXTENSIONS` and belongs to the value in `UF_PY_TOOLS` — so getting it backwards draws two rows for one pinned entry, neither of which the container ever tried to install. `resolveOnPath` decides whether a tool is *there*, and an empty `PATH` element means the current directory, so mishandling the one a trailing colon writes by accident moves every row on the page at once. `composeState` is the six-branch composition, and its expensive direction is one-way: `installed` drawn over a resolution that failed is a page telling an operator that the thing costing them money is fine. `commandPositionNames` is the only one whose grounds are a measurement rather than an argument — the leading-prefix test it replaces was measured at 10.5% recall against this install's own history — 105 commands beginning `gh ` against 1,000 that invoke it at a command position, over the 53,833 `Bash` rows in the 30-day window — and at that rate no tool ever leaves `unverified` and the reading stops carrying anything at all.

The stacks applier's five (`applyStacks.test.ts`) are the same page one mechanism over, and the shift is that a stack is an artifact **somebody else wrote**, so a refusal that does not fire fails on a machine its author never had. `parseStack` is the whole refusal list and two of its branches exist only because a second worked example found them: one `sha256` against a URL carrying `{arch}` names two files and can be true of at most one, which installs on the author's architecture and fails the digest on the other, blaming the consumer's hardware in a message nobody wrote. `refuseEnv` is `01b-` §2.2's table, and its first row is the purest instance of a silent failure in this repository — a `UF_`-prefixed key is set by the applier and then deleted by `childEnv` on the way into every agent, so the variable is configured, present on the server, and absent everywhere it was meant to matter. `expandTokens` is two spellings of one switch, `dpkg --print-architecture` saying `arm64` where `uname -m` says `aarch64`, and the assertion that earns its place is that `{arch}` must not eat the first half of `{arch_uname}`. `reconcile` is the only one here whose wrong answer is **unrecoverable**: it decides which paths a boot deletes, and the rule is that it removes only paths its own receipts record — verified against a real volume on 2026-09-12, where a file dropped into the toolbox by hand survived the boot that removed the stack beside it. Its other two rules are quiet rather than destructive: a reinstall that took `state/` would throw away a provider cache and cost a slow work cycle nobody could see, and a failed stack skipped rather than retried would make the receipt set a record of the boot that first failed rather than of this one, which is the latch `/api/status` exists not to have. `parseReceipt` (`stacks.test.ts`) is the reading end of the same boundary, and the branch that earns it is the truncated receipt a container killed mid-write leaves behind: a partial `ok` is the read-back reporting an install that did not happen, which is the failure the whole page exists to end, reintroduced by the thing that reports it. The install floor on `invocationCounts` is the one reading here that is a query rather than a pure function, and it is on the list because it is the only branch of that query whose wrong answer is a count that is too **high** — a command name outlives an install of it, and 20 `shellcheck` calls in the retained window against a binary four minutes old composed to `installed` before the floor existed.
