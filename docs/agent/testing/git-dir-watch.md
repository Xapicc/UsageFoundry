# What a run left in its repository's git directory

[← testing index](../testing.md)

Read before adding or editing tests of `gitDirWatch.ts`, `gitDirRead.ts` or `RunGitDirNotice.tsx`.

`gitDirWatch.test.ts` is the decision behind the warning, and it fails silently in both directions. A key missing from `commandClassOf`'s list is a planted command that the operator's own `git status` runs on the host, with nothing on the run's page to say so, which is the whole reason the check exists. A key that should not be on the list puts a warning on every isolated run, because this app's own git writes `.git/config` each time, and a warning that always fires is one nobody reads. So there is one case per class of command-bearing key, and each was run against a build with that class taken off the list and failed (2026-10-07). Hooks and `info/attributes` have a case each, also knocked out. One case holds everything this app writes legitimately and must come out `unchanged`; it failed when `branch.*` was made a watched key. The rest pin what a reader of the report relies on. A credential helper's text is never kept. A long `ext::` URL is still classified from its full value. Two values swapping order is a change. Section and variable compare without case, and the subsection with it. A failed reading at either end is `unreadable`, never `unchanged`. The `config-hook` case and the tool `path`, `trailer.*` and `sendemail.*` keys in the `interactive` case were added with board task `cc71aa1e` and failed as a bare `unchanged` against the code before it (2026-10-17); `diff.tool`, `merge.tool` and a host-name `smtpServer` are pinned as not watched. The `gc` case, the `guitool`, `instaweb`, `imap` and `tar` keys in the `interactive` case, and the `ext::` URLs and `svn.authorsProg` in the `remote` case were added with board task `0543690d`. Each key read as `null` against the code before it, and all three cases failed (2026-10-25). `instaweb.browser`, an `https` submodule URL and a `remote.pushDefault` naming a remote are pinned as not watched.

`gitDirRead.test.ts` is a real repository with every plant the check exists to find, and it earns its place on one property: reading runs nothing. The reader is this server's own git child, and a read that fired the fsmonitor or clean filter it was looking for would be the attack carried out by the thing meant to report it. The fixture plants an fsmonitor, a clean filter on a stat-dirty file, a textconv, an included `diff.external`, two hooks, a FIFO and a symlink. It reads at a start and an end and asserts that no marker was written. The control is a plain `git status` that writes them. A reader made to run `git status` first failed the case on the clean filter alone, because `gitArgs` clears only fsmonitor and hooks. The other cases pin where the reader looks. A folder outside any repository has nothing to read. A git directory outside every configured mount is refused, whether reached from its own worktree or through a `gitdir:` line in a checkout inside the mount. A directory whose real path moved after the start is refused at the end.

The `core.hooksPath` cases in both files were added with board task `602e9c65`, and each was knocked out in the compiled build and failed (2026-10-08). The silent failure is the one the task was filed for: a husky repository whose `.husky/_/pre-commit` a work cycle rewrote came out `unchanged`, and the new `gitDirRead.test.ts` case failed exactly that way against the code before the change. That case's control commits from a subdirectory and has git run the very file compared, so it also pins that a relative path is resolved where git resolves it. A directory that does not exist yet must read as empty, so a hook created there is `added`. Reading it as not read failed that case. A directory outside every mount, a host path the container lacks and a `~` path must each come out with a `notRead` sentence, never as a bare `unchanged`. Dropping `notRead` failed that case, and so did never reading the directory. In `gitDirWatch.test.ts`, `hooksPathOf` taking the first value instead of the last failed its case; git takes the last. A baseline from before the directory was read must not report every entry as added, and switching that filter off failed its case. `RunGitDirNotice.test.tsx` has two cases for the same reason as its others: an `unchanged` report that carries `notRead` must be a warning on the land card too, and hiding it there failed. The other pins that a hook from that directory is drawn with the directory named, in both places; drawing it as a plain `.git/hooks` entry failed it.

The submodule cases were added with board task `eb1ab9fd`. `gitDirRead.test.ts`'s case plants a `core.fsmonitor` in one submodule's `modules/<name>/config` and a hook in a second submodule whose name has a slash in it; it came out a bare `unchanged` against the code before the change (2026-10-17), and its control is the superproject's own `git status` running the plant. Not descending into a slashed name's directories failed it. In `gitDirWatch.test.ts`, a submodule one end did not read must not read as removed, and a baseline from before submodules were read must say so; dropping either guard failed its case, and so did leaving `module` off a finding. `RunGitDirNotice.test.tsx` draws a submodule's finding with the directory named, in both places, and failed with it left off.

The symlink cases were added with board task `39aaa5b2`. `gitDirRead.test.ts` builds the brief's three layouts, a symlinked `hooks/`, `info/` and `pre-commit` with their targets inside the mount, rewrites each target, and requires `changed`; all three came out a bare `unchanged` against the code before the change (2026-10-17). Their controls are `git hook run pre-commit` exiting with the rewritten status and `git check-attr` reporting the rewritten filter. A second case points each outside every mount, or at a host path the container lacks, and requires a `notRead` sentence; dropping the sentence failed it. In `gitDirWatch.test.ts`, a baseline that kept only the link must not list what is behind it as added, and must say so; switching that off failed its case.

The cap cases were added with board task `c3d33fa6`. `gitDirRead.test.ts` pads `hooks/` with 300 names that sort ahead of `pre-commit`, once after the start and once before it, rewrites `pre-commit`, and requires it `changed` with a `notRead` sentence; against the code before the change the first read it `removed` and the second a bare `unchanged` (2026-10-17). Its control is `git hook run pre-commit` exiting with the rewritten status. Reading git's names under the cap like any other, or dropping the sentence, failed it. In `gitDirWatch.test.ts`, a name past the cut at one end must not read as removed, a git hook name missing from a cut directory must, and a name new against an uncut start must read as added; dropping the cut's guard, or comparing the `…` entry, failed it.

`RunGitDirNotice.test.tsx` pins which states reach which placement, because that is decided by early returns and nothing else. A report the land card skipped, or a settled run with a baseline and no report rendered as nothing, would read exactly like a run that left the repository alone. Each of those was knocked out in the compiled component and failed. "Nothing changed" drawn on the land card failed too, since a clean run's card is meant to stay as it was.
