# The git this app runs

[← testing index](../testing.md)

Read before adding or editing tests of `git.ts` or `runTrailers.ts`.

`git.ts`'s are what every git call this app makes carries: a missing `-c` is a repository-controlled hook run by this server's own git child, with no permission mode and no line in `run_events`, and a variable that survives the scrub is that hook handed `DATA_DIR`.

`git.test.ts`'s `GIT_OPTIONAL_LOCKS` cases are a land refused for no reason of its own. `git status` refreshes the index and takes `index.lock` to write it back, and this app runs `status` in the operator's checkout from the poll behind every Land card, so a merge starting at that moment was refused by git with `Unable to create '…/index.lock': File exists`, and the lock was gone by the time anyone looked. One case asserts `gitEnv()` carries the variable and `agentEnvironment()` does not, since set there it would reach every agent. The other is a real repository with a stat-dirty file, a `status` through `git()` and the index's bytes compared, because a git that ignored the variable would pass the first; its control is a plain `status` rewriting the same index, without which a fixture that was not dirty would measure nothing. Before the change both failed. On 2.39 `git diff` against the working tree rewrites the index whatever the variable says, measured, which is why `gitEnv`'s comment requires every diff here to be between commits.

`git.test.ts`'s planted-`.git` cases are the privilege-separation half: a work cycle writes the repository's real common `.git`, so `commit.gpgSign=true` with a `gpg.program`, or a `filter.<x>.clean`/`smudge` named from `.git/info/attributes`, makes this server's own git child run a program the run chose — on the next run's `worktree add`, on commitPending's `add`/`commit`, on the Land press — outside the permission model and with no line in `run_events` (board task `9f3f9226`). One case per plant drives `git()` through `commit`, `add -A`, `worktree add` and a stat-dirty working-tree `diff --name-only` (`conflictedFiles`' shape) and asserts the marker the planted program would write never appears, with a dotted-driver-name case because git preserves a filter subsection's case and the override must match it. The control plants the same clean filter and runs it under plain git, so a `-c` that stopped carrying its pin fails the suite rather than passing silently; before the fix every plant ran and the control still passed. `before` strips `GIT_*` from the process so only `gitArgs`/`gitEnv` and the repository's `.git/config` decide, which is why an inherited `GIT_CONFIG_*` cannot outrank the plant and quietly stop the control firing.

`gitFilterProbe.test.ts` is the other half of those filter cases: the probe that names the drivers to blank had its status deliberately unread, because `git config --get-regexp` exits 1 when there are none, so a probe killed by its clock, killed by a signal or refused by git read as "no filters" and the real call ran *without* the blanks: the planted `filter.x.clean` ran in this server's git, with nothing thrown and no line in `run_events` (board task `c032f10c`). The probe is made to fail with a `GIT_BIN` stub that recognises it by `--get-regexp` and runs real git for everything else: exit 128 with a stderr, `kill -9` of itself (a null code with a signal, which needs no clock and so serves `gitSync` too, whose 20 s clock is `spawnSync`'s own and cannot be mocked), a real `sleep` killed by a 400 ms caller clock for `git()` only, and exit 1 *with* output. Each asserts first that the marker the planted program writes is absent and then that the call failed with a reason that names the probe and how it ended, and all six failed before the change with the marker present. Two cases passed before and are there to keep it so: a repository with no filters, where real git answers exit 1 with nothing and the call must still run, since a check that failed that too would fail every `add` this app makes; and a `rev-parse` with the probe broken, since the probe is only for the content subcommands. Its `a=b` cases are the neutraliser's own: git splits a `-c` at its first `=`, so a clean filter named `a=b` ran under `git()` and `gitSync()` with its blank in place, and both cases failed with the marker present until the blanks moved to `--config-env` (board task `a9fde194`); a plain-git control keeps a plant that stopped firing from passing them. Its empty-name cases are the same neutraliser's: git reports `[filter ""]` as `filter..clean`, which a name pattern wanting one character never matched, so a `* filter=` or `* merge=` line ran the program on `add`, `merge-tree` and `merge` through `git()` and `gitSync()` (board task `582bceef`). `[hook ""]` has the same key shape, and its case skips on a git that reads no `hook.*` key, as `git.test.ts`'s do; four cases failed with the marker present on 2.39.5 and five on a built 2.56.0. Its merge-driver cases plant `merge.evil.driver` with `* merge=evil` over two branches that change different lines of one file, so the merge is a three-way content merge: `git()`'s `merge-tree --write-tree` and `merge` both ran the driver before the probe listed `merge.*` and `merge-tree` was gated, and must now run nothing and fail rather than report a merge (board task `a38856ec`); an `a=b` driver name and a plain-git control ride along. Its conditional-include cases put filter `evil` in a file reached only through `includeIf "onbranch:uf/**"` or `"gitdir:<repo>/.git/worktrees/"`, which the probe in the operator's checkout cannot see and the child inside a worktree can: `git()`'s `worktree add` ran the smudge and its `worktree remove` of a stat-dirty tree ran the clean filter, in both forms, until a plain add was refused and a remove probed in its tree (board task `d8cae532`). `addWorktree` is asserted to leave a whole, unlocked checkout with nothing run, and, when its checkout fails, no tree and the branch kept, since a half-made tree left behind is refused at the next start as uncommitted work. `git.test.ts`'s smudge case goes through `addWorktree` for the same reason. Its own file because `GIT_BIN` is read when `config.ts` loads.

`gitFilterProbe.test.ts`'s submodule cases plant a filter in a submodule's own git directory, which the probe in the superproject never read, and the child git a content subcommand starts inside the submodule did: `status` of the superproject (from its top, from a subdirectory, and through `gitSync`), `add -A`, which no flag or setting stops recursing, and a submodule inside a submodule each ran it, until every populated gitlink became a probe site (board task `a559b561`). Three more reach a submodule the index before the call does not list, and each ran its plant until it was pinned off: `read-tree -u` onto a commit adding one under the repository's `submodule.recurse` (`submodule.recurse=false`), `checkout` onto a branch whose index alone lists one (`--quiet`), and a patch of a submodule move under `diff.submodule=diff`, which ran the submodule's textconv past `--no-textconv` (`diff.submodule=short`). One plain-git control fires every plant, `add -A` under every ignore setting. Its race cases make the probe-then-call race deterministic with a stub that answers the probe from the configuration as it was and then writes the driver (board task `7d41bb25`): a `.git/config` rewritten that way ran the driver under `git()` and `gitSync()` and must now refuse the call naming the file, and an included file written while the index is listed must refuse it too. The included case passed its marker check before the change only because no listing step existed for the stub to write in; its control writes the include by hand. Its two merge-driver wording cases pass `git()`'s failure through `parseMergeTree` and `gitFailureLine`, the two readers that keep one line, and assert the blanked driver is named there (board task `adb9e828`).

`git.test.ts`'s config-hook cases are the same plant for git 2.54's hooks defined in config, which `core.hooksPath=/dev/null` does not reach (board task `6b4dccf3`, `security/path-containment-and-spawn-argv.md`). Each writes `hook.<name>.command` and `.event` and drives `git()` through a call that fires the event: `commit` through `git()` and `gitSync()`, `update-ref` and `branch -D` with `reference-transaction`, `push` with `pre-push`, and names `a.b`, `MiXed`, `sp ace` and `a=b` because git keeps a subsection verbatim and splits a `-c` at its first `=`. Two more plant the hook in a second git that this app's git starts: a `commit` whose automatic maintenance runs `gc --auto` (`maintenance.strategy=gc` and two packs against `gc.autoPackLimit=1`), and a `push` that `push.recurseSubmodules=on-demand` sends into a submodule whose own config defines `pre-push`. The second also asserts the submodule's remote got nothing, since that push goes to a remote no door checks. All six failed with the marker present before the change, on Apple git 2.54.0. A git that reads no `hook.*` key cannot run a plant at all, so the cases skip there rather than pass having measured nothing; the control that decides it is a plain-git commit in `before`, and the last case asserts each plant fires under plain git. On the image's 2.39.5 they skip, so the gate is pinned separately in `gitFilterProbe.test.ts`, where a probe that fails is how being asked shows on any git: `branch -D`, `update-ref`, `fetch`, `push`, `remote rename` and an unmeasured `tag` must fail closed, which the first four did not when the gate listed only content subcommands, and `commit-tree` and `check-ignore` behind a leading `-c` pair, bare `remote` and `remote get-url` must not ask, since a gate reading `args[0]` takes `-c` for the subcommand.

`git.test.ts`'s `GIT_BIN` case plants a `git` first on `PATH` and asserts `gitSync` did not run it. The default was the bare name, and this server's `PATH` then started with the stacks' `bin/` and the agent-owned `/home/node/pytools/bin`, so whatever `git` was first there answered every diff, worktree and landing — as root wherever the uid split is off. Root's `PATH` no longer carries either (board task `aff25da4`); the case stays because the path is what keeps git from depending on that. Nothing about that is visible: a planted `git` that forwards to the real one passes every other test in the suite. Skipped when `GIT_BIN` is set, because the default is then not what runs.

`runTrailers.test.ts` and `runTrailersCycle.test.ts` are the commit trailers (`isolation-and-landing/commit-trailers.md`), and every way they fail is silent: a run that completes and a branch that lands with commits as anonymous as before, a model id that forges a second trailer, an author moved by a rewrite, or a commit the target already has re-made. The first file runs `stampBranchCommits` against real repositories and asserts what must not change as hard as what must: tree, author, committer and dates identical, the operator's branch where it was, a second pass moving nothing, a merge of the target into the branch keeping the target's own commit as its second parent, a tip an earlier run landed and everything under it left as it was, another run's stamped commit left alone with the ones above it stamped, and a commit with an `encoding` header stopping the whole stamp with the branch unmoved. With the target left out of the `rev-list` five of its twenty cases fail. The second drives a real run through `createRun` with a stub agent that commits in its working directory (`cutOffCheckout.test.ts`'s harness), because the stamp is one call in the run loop and a test of the module cannot see it missing: removing the call fails the isolated-run case, and the second case holds that a run in the operator's own checkout is not rewritten. The commits the app makes itself are asserted where their land is, not here: `landAfterVerify.test.ts`' last describe (squash, merge, the Commit button, a Dreaming night), `landAfterSquash.test.ts` (a merge landed past a squash and a resolution's merge past one) and `resolutionMarkerless.test.ts`' control (a conflicted resolution's message is exactly the subject and one trailer block, with no `# Conflicts:` comment). Those last two compare the whole message, because a duplicated block passes a `match`.
