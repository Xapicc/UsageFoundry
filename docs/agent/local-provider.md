# The local provider

> **Read before editing `localProvider.ts`, `localCertification.ts`, `/api/local-provider`, the `local` branch of `runIteration` or the cycle loop in `orchestrator.ts`, `certificationOf` in `land.ts`, or the verdict a review of a local branch is asked for in `review.ts`.**

A third value of `runs.provider`: a model behind an Anthropic-compatible API on a machine the operator runs, signed into from Settings > Local model. Experimental, on the `local-provider` branch. Every rule below fails silently — nothing throws, and a local run that broke one looks like a local run that worked.

- **A local run is Claude Code pointed elsewhere, and the difference is the environment and nothing else.** `selectCycleAdapter` hands it `CLAUDE_ADAPTER`, so the argv, the stream parser, the process-kill denial, the appended system prompt, plugins and the taskboard are all the Claude path's. What differs is applied in `runIteration` *after* `childEnv` has run, by `localCycleEnv`, so every strip `childEnv` carries still applies and this only removes more and sets the rest. A third CLI adapter was the alternative and would have had to earn each of those guarantees again.

- **Winnow is bypassed per child, never stopped.** The entrypoint exports `ANTHROPIC_BASE_URL=http://127.0.0.1:8789` into the server's environment (measured on the live container 2026-09-27: no `HTTP(S)_PROXY` beside it), and `childEnv` passes it to every agent. A local cycle's base URL is overwritten, so its requests go straight to the local server and never through the intake filter, while every Claude run in flight beside it keeps going through it. Stopping the proxy while a local run is up would take the API away from those runs — the entrypoint's own comment says killing it "turns the API off". **The proxy has a second half the base URL does not undo:** the entrypoint also exports `ENABLE_TOOL_SEARCH=1`, because a non-Anthropic base URL turns tool deferral off and winnow forwards the `tool_reference` blocks `ToolSearch` answers with. A local server does not — LM Studio refused the first one with `400 request.messages.3.content.0.content.0.type: Invalid literal value, expected "text"` and the run ended there (2026-09-28, the first real local run). So `localCycleEnv` sets it to `false`, and every tool's schema rides every request. The pruner and the context ceiling go quiet by a second route: both find a run's transcript under `PROJECTS_DIR`, and a local cycle writes none there.

- **A local cycle has its own `CLAUDE_CONFIG_DIR`, and that is what keeps it out of every meter.** `LOCAL_CLAUDE_CONFIG_DIR` is the sibling `.claude-local` (`/home/node/.claude-local` in the container). Its turns written into `~/.claude/projects` would be an unpriced model to `guardCostOf`, which charges the fallback rate against the plan's windows — a run that spent nothing of the subscription would park the Claude runs that do — and the dreaming corpus, repository spend and the intake ledger's join all read the same tree. A sibling rather than a directory inside `~/.claude`, because that is the operator's host tree. It is the writable layer, so a parked local run's session does not survive `docker compose up --build`; `ensureLocalConfigDir` creates it per cycle and hands it to the agent uid, and throws rather than degrading. **It also symlinks the operator's `CLAUDE.md` and `rules/` into it**, because a separate config directory took those away too: the first local run a frontier review rejected (45e27aad, 2026-09-28) had loaded the repository's `CLAUDE.md` and none of the five rule files a Claude run gets, and three of the review's four findings were those rules broken. Instructions only — `settings.json` stays out, since its hooks and `env` are the operator's Claude setup and an `env` there could point the CLI back at Anthropic. A real file or directory at either name is left alone.

- **The subscription credential can never reach the local server.** `localCycleEnv` removes `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN` and `ANTHROPIC_CUSTOM_HEADERS`, removes the Bedrock and Vertex switches that would make the CLI ignore the base URL, and **always** sets `ANTHROPIC_AUTH_TOKEN` — to `LOCAL_TOKEN_PLACEHOLDER` when the server wants none. Unset, the CLI falls back to the OAuth login and sends it to whatever the base URL names; the pinned 2.1.280 ranks this variable above that login ("ANTHROPIC_AUTH_TOKEN is set, so this session is using API-key auth"), read out of the binary, and measured against a stub server on 2026-09-27: the request carried the local bearer and no `x-api-key` with a fake account key in the input (`docs/verification/other-providers.md`). The separate config directory holds no `.credentials.json` either. `ANTHROPIC_API_KEY` is the one credential `childEnv` deliberately passes; this is the one child that must not get it.

- **Every model role is named, not only `--model`.** Claude Code also calls a small model for housekeeping and its own model for a sub-agent; each would reach the local server under a Claude id. `ANTHROPIC_MODEL`, the three `ANTHROPIC_DEFAULT_*_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL` and `CLAUDE_CODE_SUBAGENT_MODEL` all carry the run's model — all six present in the pinned binary.

- **Spend is unknown, not zero, and so is live telemetry.** Claude Code does report `total_cost_usd` for a local cycle, priced from a table that has never heard of the model, so `providerReportsSpend` answers false and the loop withholds the `+=` exactly as for Codex. The same figure is why the OTLP variables are stripped, and why `--max-budget-usd` is never passed on a local cycle: the CLI would end a cycle on a price nobody was charged. A live token guard therefore only acts between cycles on a local run. `providerTerminusRefusal` requires a cycle or time limit for the Codex reason, which is now also true here.

- **The sign-in is a probe and a row.** `POST /api/local-provider` asks `POST {baseUrl}/v1/messages` for one token with the bearer a cycle will send, and saves nothing unless the answer is an Anthropic `message` — a server that speaks only the OpenAI dialect answers a model list perfectly well and then fails every cycle. It lives in the `local_provider` table rather than `settings`, which `GET /api/settings` serves, and under `/data` rather than the agents' home because the server reads it and hands it to one child at a time. The page gets `hasToken` and never the token; `credential-audit.test.ts` pins that for both tables and the answer. A pasted `…/v1` is refused, because the CLI appends `/v1/messages` itself.

- **The model is frozen at the door and the endpoint is read per cycle.** `POST /api/runs` refuses a local run while signed out and freezes the sign-in's model (or the one the form named) onto `runs.model`, so a run keeps its model when the sign-in later names another. The base URL and token are read at every cycle, so a sign-out refuses the next cycle of every local run — refused rather than degraded, because the only other place that cycle could go is Anthropic, under the plan a local run exists not to spend.

- **The chat can propose a local run, on the same terms as the form.** `propose_run` refuses `provider: "local"` while signed out and refuses a model with it (every id the tool offers is a Claude one); `planProposal` drops the template's model for it; and `approveProposal` reads the sign-in at the click — refusing without failing the proposal while signed out, since signing in again clears it — and freezes the sign-in's model onto the run, as `POST /api/runs` does. The card states it with a one-line warning. See `docs/agent/chat/what-a-model-may-write.md` for why a proposal may name a provider at all.

- **A branch any local run committed to does not land and is not delivered until a frontier model's review of its tip says APPROVE.** `certificationOf` in `landState` asks `localRunsOnBranch` — by `repo_root` and `worktree_branch`, not by walking `continues_run`, so a Claude run carrying a local run's branch on is held too — and reads the landing run's latest review. `certificationRefusal` is appended *after* `landRefusal`, so a conflict or a dirty checkout is named first (resolving one moves the tip and would need a second review), and Deliver asks it directly, because Deliver reads `certification` and never `blocked`. The merge queue and a workflow's merge block land through `landRun`, so both inherit it. An approval certifies the commit the reviewer was shown (`run_reviews.head_sha`, written at the start of the review) and nothing after it, a conflict resolution included.

- **The frontier model is the existing review, held to a verdict.** A review of such a branch is asked for a fourth heading, `## Verdict`, with exactly `APPROVE` or `REJECT`; `parseCertificationVerdict` reads the last such heading and the first line under it whole, so "APPROVE with caveats" is no verdict and certifies nothing. `assistModel` hands a local run's review the Claude default rather than the local id, and `isFrontierReviewModel` refuses a Haiku or any id `pricing.ts` cannot place — null, the CLI's own default, counts as frontier, which is an assumption about the plan rather than a measurement. Every other review is unchanged.

- **What this does not stop.** An operator merging the branch by hand with git, outside the app. A pull request opened by hand from a pushed branch. An agent in a local run that pushes its own branch with the install's GitHub token.
