# A task already done in the branch's history

[← taskboard index](../taskboard.md) · [← the validation rules](completion-validation.md)

Read before editing `src/lib/validationHistory.ts`, the `history` argument of `buildValidationPrompt`, or `deliveredBefore` and `historySearchStart` in `src/lib/validation.ts`.

**A branch diff, empty or not, is read beside the commits the server finds already in the history it starts from, and never beside anything the run says.** The judge reads the branch's diff, and its prompt takes an empty one against a task that required a change as `not-finished`. A task whose fix reached the branch another way — through the target the branch was updated from, or because the branch was started after the fix landed — leaves exactly that diff, so "already done by someone else" and "did nothing" were the same evidence, and the run could not close a task that was done (board task `17be140e`: a Dockrac run, session `5e95e960`, held a task whose fix `c267d6a2` was an ancestor of its `HEAD`; the close was refused and the run released it operator-only for a person to close). The alternative was to record that a person closes such tasks. It was not taken because the evidence can be the server's own and the measurement the prompt's doc demands could be run (below), and the cost of the status quo is a stranded task and a billed pick-up each time.

**Evidence is two server-side facts, and a commit hash the run names is neither.** A commit counts only if it carries exactly one `UF-Run` trailer that is not the judged run's, a `UF-Task` trailer naming this task, and `run_tasks` records that `UF-Run` as started for this task. The trailers are written by `stampBranchCommits` after the agent's process has exited (`runTrailers.ts`), and `run_tasks` is the board's own table, so the run cannot supply either half: the tool takes no hash, and a commit message that merely mentions the task id is text another agent wrote and is not read. The first draft of this was "the commit the run names, checked with `git merge-base --is-ancestor`", and it was dropped because an ancestor check proves a commit exists in the history and nothing about it being *this task's*: any old commit would pass.

**A matching trailer finds a commit; the judge still reads it.** A run holding two tasks stamps both ids on every commit, so a trailer says "a run started for this task made this" and not "this contains the deliverable". Closing on the trailer would turn a commit made for a sibling task into a done one, which is the false-finished the validator exists to prevent. So `alreadyDeliveredFor` hands the judge the commits' patches (the run's own diff budget, `VALIDATION_DIFF_BYTES`, shared between them; at most `HISTORY_COMMITS_SHOWN` commits out of the last `SCAN_COMMITS` it searched), and the framing in `historyEvidence` says so in as many words, routes "cannot settle it" to `unjudgeable`, and, like the preamble, says nothing of what an answer causes.

**A diff with files asks too, from where it starts, and under its own framing (board task `813c54f5`).** It first did not: with a diff to judge the question looked already answered by what the run committed, and showing an earlier run's commits beside a later run's risked the judge reading one run's half as the other's. The other side of that error was a task worked across two runs, whose later run commits only its half, judged `not-finished` for the deliverables the earlier run had delivered, so the pushback bought a billed cycle to redo work that exists. The measurement below is why it was widened. Two things make the widening not simply a dropped condition. **The search starts where the diff starts** (`historySearchStart`: the target commit the diff is measured from, else the run's base), because the commits from there on are the diff and searching from the head would show them twice, the second time as another run's history. **The framing is different**: the empty-diff opening says the branch's own diff is empty, which would be false above a diff with files, so `historyEvidence` opens with "the diff above is this branch's own, and it may be only part of the work" and asks the judge to read the diff and the commits together. The middle paragraph, what the trailer proves and does not, is shared word for word, and the prompts of an empty diff and of no history are byte-identical to what they were (28 and 40 requests compared across the change).

**Every failure is "no evidence", which is today's behaviour.** A log that cannot be read, a commit whose diff cannot be read (`wholeCommitDiff` in `diff.ts` returns null), a path outside its mount (`repoPathFor` is the same containment `runDiff` applies), a run row retention has removed: each leaves the judge the empty diff it always had. The read happens before `runStoppedBeforeCheck` and not after, because that check's whole point is that nothing is awaited between it and the start. The run's log says which commits were shown.

**What this does not cover, so a person still closes these.** A fix made by hand, or by a run started for a different task, has no `UF-Task` trailer for this one. The incident that raised this (`c267d6a2`, Dockrac) predates the trailers: it names the task in its message body only, so this change would not have closed *that* task, and a rule reading free text would have had to trust a string any commit author can write. A run row removed by retention takes its `run_tasks` link and the evidence with it. Both leave the status quo, a person closing the task.

**The measurement, 2026-11-08, and what it does and does not show.** `scripts/validator-spike/history.mjs` builds three arms from the seven single-commit cases the spike labelled `finished` and kept whole (3, 4, 5, 11, 13, 30, 35), all with an empty branch diff, composed by the production `buildValidationPrompt` from a compiled build; `io-history/` holds the replies and `history-report.md` the tally. *today* (no history, what the judge sees now): **7 of 7 `not-finished`** for work that is in the history — the incident, reproduced. *match* (the case's own diff as history): **7 of 7 `finished`**. *mismatch* (another case's diff, two pairings, six of the fourteen pairs touching a file the task's own fix touched): **0 of 14 `finished`, 14 of 14 `not-finished`**. Caveats, all of which narrow the claim: one sample per request and no variance; **n = 7 per arm, so 0 of 14 false-finished has a 95% upper bound near 21% and bounds nothing tighter**; the judge was a Claude Code subagent on this run's model (Sonnet 5.5), not `spawnAssist`'s child under `plan` mode, and the spike's own 40 were Sonnet 4.5; the task text is `runs.task` as the spike recovered it, not a board title and brief; the history text is rebuilt from the stored diff and not read from git, so `wholeCommitDiff`'s own output was exercised only by `validation.test.ts`; the "mismatch" label rests on the diffs being obviously for other work, which the judges' reasons bear out and no person re-read; and 16 of the 28 replies reached me in the subagent's message rather than in a file (9 against its instruction, 7 by it) and were saved verbatim by hand. The shipped preamble (`VERDICT_PREFERENCE`) is **not** `prompt.md`'s; this scores it on empty-diff inputs only, and its agreement on the 40 (32 of 37, zero false-finished) is the separate measurement in `scripts/validator-spike/RESULT.md`.

**The measurement for a diff with files, 2026-11-08, and what it does and does not show.** `history.mjs --arms split` (`history-split-report.md`, `io-history-split/`) cuts six multi-commit cases the spike labelled `finished` and the shipped preamble also called `finished` whole (12, 16, 17, 25, 33, 37) into an earlier part, shown as history, and a later part, the diff, with each commit's real diff read from its repository (`wholeCommitDiff`). *today* (the later part alone): **0 of 6 `finished`**, 3 `not-finished` (12, 17, 37, where the diff plainly lacked files the task names, the incident reached with a non-empty diff) and 3 `unjudgeable`. *history* (the later part and the earlier commits): **5 of 6 `finished`**, the sixth (12) `unjudgeable` because its `page.tsx` patch was cut. *mismatch* (the later part and another case's earlier commits, two pairings): **0 of 12 `finished`**, and each verdict was the one the same diff had got with no history at all, 12 of 12. *partial* (the first commits as history and a diff that skips the middle ones, so a named deliverable is in neither; 12, 25, 33): 0 of 3 `finished`. **False-finished is 0 of 15.** The rule the task set was that false-finished stay 0 and the new arm beat the old; both held, so `deliveredBefore` was widened. Caveats, all of which narrow the claim: **n = 6 an arm and one sample per request, and 0 of 15 bounds the false-finished rate only below about 18%**; the splits cut one run's commits in two and no task worked across two real runs was observed, so the shape of a real later run's diff against its earlier run's is inferred; the six cases were chosen after the whole-branch verdicts were known (7 and 19, which the preamble could not settle whole, and 14 and 29, whose earlier commit is larger than the 60 KB history budget, were not run), which favours the new arm; 3 of the 12 mismatch pairs touch a file the task's own work touched and the rest are other work in the same repository or another one, so a near miss on the same function is untested; the judge was a Claude Code subagent on Sonnet 5.5, not `spawnAssist`'s child under `plan` mode; and 5 of the 27 replies reached me in the subagent's message and were saved verbatim by hand. A `unjudgeable` answer closes the task like `finished` does, so it is not a safe outcome for work that is not done: the mismatch and partial arms gave 8 of 15 of them, and for the 14 whose diff was also judged with no history each was the verdict that diff got alone, so what the history changed there was nothing.

**To measure again** (the prompt is an instrument, so any edit to `historyEvidence` or the preamble needs it): `npx tsc -p tsconfig.test.json --outDir .test-build/spike`, `node scripts/validator-spike/history.mjs --emit --io-dir <dir> --build-dir .test-build/spike` (`--arms split` for a diff with files), answer each `<dir>/<name>.request.md` into `<dir>/<name>.response.md` with a judge that has no repository access, then `--collect --io-dir <dir>`. About $0.10 a request on the subagent path.
