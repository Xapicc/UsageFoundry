# Stacks

[← security index](../security.md)

Read before editing `scripts/apply-stacks.mjs`, a `stack.json`, or the stacks steps in `Dockerfile` and `docker-entrypoint.sh`.

- **A stack is software the operator chose to install, and what this mechanism buys is that the choice is reviewable and revocable rather than safe.** `scripts/apply-stacks.mjs` reads a `stack.json` a third party may have written, downloads what it names, verifies it against the publisher's own digest and links the result into a directory on every agent's `PATH`. The honest sentence is `01b-` §6's and belongs here rather than in a proposal: *consuming a third party's stack is the same act as taking their `RUN` line into your Dockerfile.* What is bought is that the act is one small file — every URL, digest and denied command visible — and that deleting the directory and restarting undoes it. What is **not** bought is any check on where the URL points: there is no host allowlist and no signature verification, because this repository holds no key material and inventing a trust root is a larger decision than this mechanism. Four things enforce the rest, and each is load-bearing. **Never a shell**: the applier interpolates into argv arrays and `spawnSync` without `shell`, so a URL or a filename out of somebody's file is inert the same way a prompt's metacharacters are at the spawn sites above — the format's four expansion tokens exist precisely so an author never reaches for `$( )`. **Verify before unpack, and `archive` executes nothing**: the digest is checked with the image's own `sha256sum --ignore-missing --check` before anything is extracted, and nothing downloaded runs until an agent runs it, which is why `archive` shipped alone and ahead of the two verbs that run a package's install hooks. **The uid split inverts here on purpose**: download, verify, unpack and `chmod` drop to `UF_AGENT_UID`, and the `chown root:root` and the `install -m 0755` into `bin/` are root's — the opposite of the gh and Python loops, because `bin/` is on the *server's* `PATH` and a directory there that a sibling agent can rewrite is a way for one run to put its own code on every other run's transcript. `/home/node/pytools/bin` is already one of those; there is not a second. The split is safe only because the applier runs before `exec "$@"`, in the one window with no agent process alive. And **a stack's `env` is a denylist that fails closed at parse**: `refuseEnv` refuses every `UF_*` key (which `childEnv` would delete after the stack set it, silently), the names that decide where things are, any value carrying a shell metacharacter, and anything resolving under `/home/node/.claude` — which is the *host's* `~/.claude` for every session on the machine. `deny` entries are refused unless their first word is a binary the stack itself links, and that rule is doing the opposite job from the one it looks like: it stops a stack **denying** what it does not own, since deny beats `ISOLATED_GIT_TOOLS` the same way it beats the mode, and a stack that could write `git commit` there would break every isolated run on the install.

- **A stack is software you chose to install, and this mechanism makes that act reviewable and revocable rather than safe.** Consuming a third party's `stack.json` is the same act as taking their `RUN` line into your `Dockerfile`. What it buys is that the act is one small file an operator can read in thirty seconds — every URL, digest and denied command visible — and that undoing it is `rm -r` and a restart. It does not make it safe, and nothing that installs software can. What is verified is the artifact against the publisher's manifest before it is unpacked, which is `Dockerfile:163-175`'s own pattern; a URL is not checked against an allowlist of hosts, and **there is no signature verification**, because this repository holds no key material and inventing a trust root is a larger decision than the design made. The trust boundary is the stack and not the digest: an author who writes the digest is the author who wrote the URL, so `checksums` — the publisher's own manifest — is the documented form and a literal `sha256` exists only for a publisher who ships none. **The three verbs differ in what they trust.** `archive` executes nothing it downloads, ever, so a stack using it is worth exactly its URL; `uv-tool` and `npm-global` run the package's install hooks as the agent uid at boot, so a stack using either is worth the package it names — which is the trade `docker-entrypoint.sh:233` already makes for `UF_PY_TOOLS` and is stated rather than glossed. **What a stack may never do is decided at parse, before a byte is downloaded**: no `UF_*` environment key (`childEnv` would strip it after it was set), none of the names that decide where things are, no `bin.from` escaping `{pkg}`, no `deny` entry naming a binary the stack does not itself link — that last one not to stop a stack granting what it should not, but to stop one *denying* what it does not own, since deny beats `ISOLATED_GIT_TOOLS` the same way it beats the mode and a stack that could write `git commit` there would silently break every isolated run on the install. Nothing downstream re-checks any of it, deliberately: a second gate is a second thing that can disagree with the first about what a stack may grant, and the receipts it would be re-checking are root-owned in a volume no agent can write.
