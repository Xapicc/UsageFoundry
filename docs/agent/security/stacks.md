# Stacks

[← security index](../security.md)

Read before editing `scripts/apply-stacks.mjs`, a `stack.json`, or the stacks steps in `Dockerfile` and `docker-entrypoint.sh`.

- **A stack is software the operator chose to install, and what this mechanism buys is that the choice is reviewable and revocable rather than safe.** `scripts/apply-stacks.mjs` reads each `stack.json` under `/etc/uf-stacks` — one a third party may have written — downloads what it names and links the result into `/var/lib/uf-stacks/bin`, which the image puts first on the server's `PATH` and so on every agent's. The honest sentence is `proposals/CustomStacks/01b-stack-format.md` §6's and belongs here rather than in a proposal: *consuming a third party's stack is the same act as taking their `RUN` line into your Dockerfile.* What is bought is that the act is one small file an operator can read in thirty seconds — every URL, digest and denied command visible — and that `rm -r` of its directory and a restart undoes it: the next boot removes the package, its state, the links its receipt records and the receipt. Editing the file into one the parser refuses is not the same act, because that records a `failed` receipt and removes nothing installed before it. None of this makes the act safe, and nothing that installs software can. What is **not** bought is any check on where a URL points — the parser requires `https://` and nothing more, there is no host allowlist and **there is no signature verification** — because this repository holds no key material and inventing a trust root is a larger decision than this mechanism. **The three verbs differ in what they trust.** `archive` executes nothing it downloads, ever, and verifies it before unpacking with `sha256sum --ignore-missing --check`, the pattern of the `gh` download at `Dockerfile:199-203`, so a stack using it is worth exactly its URL — which is why it shipped first and alone. The trust boundary is the stack and not the digest: an author who writes the digest is the author who wrote the URL, so `checksums` — the publisher's own manifest — is the documented form and a literal `sha256` exists only for a publisher who ships none; the parser takes exactly one of the two and treats them alike. `uv-tool` and `npm-global` verify nothing and run the package's install hooks at boot, as `UF_AGENT_UID` when that is set and as root when it is not, so a stack using either is worth the package it names — the trade `docker-entrypoint.sh`'s `UF_PY_TOOLS` loop already makes through `uv_install_tool`, stated rather than glossed. Three more things enforce the rest, and each is load-bearing. **Never a shell**: the applier interpolates into argv arrays and `spawnSync` without `shell`, so a URL or a filename out of somebody's file is inert the same way a prompt's metacharacters are at the spawn sites above — the format's four expansion tokens, `{arch}`, `{arch_uname}`, `{state}` and `{pkg}`, exist precisely so an author never reaches for `$( )`. **The uid split inverts here on purpose**: download, verify, unpack and the `chmod` of what was unpacked drop to `UF_AGENT_UID`, and the `chown -R root:root`, the `chmod -R go-w` after it and the links into `bin/` are root's — the opposite of the gh and Python loops, because `bin/` is on the *server's* `PATH` and a directory there that a sibling agent can rewrite is a way for one run to put its own code on every other run's transcript. `/home/node/pytools/bin` is already one of those; there is not a second. The split is safe only because the applier runs before `exec "$@"`, in the one window with no agent process alive. And **what a stack may never do is decided at parse, before a byte is downloaded**, in `parseStack`. A stack's `env` is a denylist that fails closed: `refuseEnv` refuses every `UF_*` key (which `childEnv` would delete after the stack set it, silently) and the `GIT_`, `CLAUDE_`, `ANTHROPIC_`, `OPENAI_` and `CODEX_` prefixes, the names that decide where things are (`PATH`, `HOME`, `NODE_OPTIONS`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `DATA_DIR`), any value carrying a shell metacharacter, and any absolute value that normalises under `/home/node/.claude` — which is the *host's* `~/.claude` for every session on the machine. No `bin.from` may escape `{pkg}`. A `deny` entry is refused unless its first word is a name the stack itself links, and that rule is doing the opposite job from the one it looks like: it stops a stack **denying** what it does not own, since deny beats `ISOLATED_GIT_TOOLS` the same way it beats the mode, and a stack that could write `git commit` there would silently break every isolated run on the install. No linked name is reserved, so a stack that links a `git` of its own owns `git` in that sense, and its `git` is the one first on every `PATH`. Nothing downstream re-checks any of it, deliberately: a second gate is a second thing that can disagree with the first about what a stack may grant, and the receipts it would be re-checking are root-owned files in `/var/lib/uf-stacks/receipts`, which no agent can write.
