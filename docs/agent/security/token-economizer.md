# TokenEconomizer: what its hooks can reach and what nobody meters

[← security index](../security.md)

Read before editing `tokenEconomizerFor`, `tokenEconomizerEnv` or `ensureTokenEconomizerCatalog` in `src/lib/tokenEconomizer.ts`, the `tokenEconomizer*` settings, or the TokenEconomizer blocks of `Dockerfile`, `docker-compose.yml` and `docker-entrypoint.sh`. How it is loaded is in `architecture/module-map-agent-tooling.md`.

- **The code is root-owned and the state is not, and both facts are deliberate.** `/opt/tokeneconomizer` is in the image, root-owned and `a+rX`, so no agent can rewrite what every agent's hooks execute. Its state root, `/home/node/.tokeneconomizer`, is a named volume owned by the agent uid, because the hooks run as that uid and write what they learn there. So **every work cycle can write the plugin's config files and its learned facts**, and the plugin's hooks run with the agent's authority, not the server's.
- **Environment pins stop config overrides and stop nothing else.** `TE_TOOLPRUNE`, `TE_MICROSKILLS` and `TE_LOOPGUARD` are always set (`off` included) and outrank the config files, so a cycle cannot switch a mechanism on by writing a file; `TE_PYTHON=/usr/bin/python3` stops the agent-writable `pytools/bin` from supplying the interpreter. `TE_TOOLPRUNE_PROTECT=mcp__uf__*` is pinned for the same reason and is **not an operator setting**: it keeps this app's own MCP tools (the board's and `request_stack`) out of tool pruning in every repository, and the plugin takes the env value *instead of* the config files' `toolprune_protect`, so a cycle cannot un-protect them by writing one — and a protect list the operator wrote there is not in force for these cycles. The pattern is built from `MCP_SELF_SERVER` (`config.ts`), the key `writeMcpConfig` names the server under. What the pins cannot stop is a cycle planting *content*: with micro-skills on, a cycle can write facts that are injected into later sessions of **any** repository the plugin has seen. That is why micro-skills ships `off` and `envfacts` is the narrower setting.
- **Tool pruning writes into a checkout, and this app copies it across them.** The plugin adds `permissions.deny` to `<checkout>/.claude/settings.local.json` of the checkout whose session produced the list, and the path to the repository's shared `.git/info/exclude`, so a reused worktree slot stays clean and keeps it. A repository's runs spread over a dozen or more slots, so `seedTokenEconomizerSlot` applies the repository's union to a slot before a new session opens there, through the plugin's own `toolprune apply`. **That widens what a planted state file reaches**: the union is read from `untool_applied.json`, which every cycle can write, so a planted tool name is copied into every new slot rather than into the one the plugin would have written. Three things narrow it: only tool names pass (`denyListToSeed`), never a permission pattern such as `Bash(rm:*)`; a tool given back with `toolprune restore` anywhere is seeded nowhere; and no `mcp__uf__` tool is ever seeded, because the plugin's fold removes a rule it wrote for a protected tool only from the checkout it folds while `untool_applied.json` can still list one from before the protection or one a cycle planted. What remains is denial of a tool, not a grant. The operator's own folder is written only by runs that work in it directly, and the operator's interactive Claude Code sessions there read the same file. The first list in a repository waits for the quiet period (`tokenEconomizerQuietMinutes`, 60); `propose` mode exists so the operator can see a list before `auto` acts on it.
- **Its side calls are invisible to every meter.** The loop guard's judge and the micro-skill proposer are `claude -p --no-session-persistence` calls billed to the plan and written to no transcript, so `runs.spent_usd`, the windows and every budget guard here are blind to them. The loop guard therefore ships `off`, not at the plugin's own default of `nudge`; do not move it without a meter that sees these calls.
- **Codex and local runs get nothing.** A local cycle would hand the plugin's model calls an endpoint with no `haiku`, and its turns would teach the repository's Claude history another model's turn length.
