# TokenEconomizer: what its hooks can reach and what nobody meters

[← security index](../security.md)

Read before editing `tokenEconomizerFor`, `tokenEconomizerEnv` or `ensureTokenEconomizerCatalog` in `src/lib/tokenEconomizer.ts`, the `tokenEconomizer*` settings, or the TokenEconomizer blocks of `Dockerfile`, `docker-compose.yml` and `docker-entrypoint.sh`. How it is loaded is in `architecture/module-map-agent-tooling.md`.

- **The code is root-owned and the state is not, and both facts are deliberate.** `/opt/tokeneconomizer` is in the image, root-owned and `a+rX`, so no agent can rewrite what every agent's hooks execute. Its state root, `/home/node/.tokeneconomizer`, is a named volume owned by the agent uid, because the hooks run as that uid and write what they learn there. So **every work cycle can write the plugin's config files and its learned facts**, and the plugin's hooks run with the agent's authority, not the server's.
- **Environment pins stop config overrides and stop nothing else.** `TE_TOOLPRUNE`, `TE_MICROSKILLS` and `TE_LOOPGUARD` are always set (`off` included) and outrank the config files, so a cycle cannot switch a mechanism on by writing a file; `TE_PYTHON=/usr/bin/python3` stops the agent-writable `pytools/bin` from supplying the interpreter. What the pins cannot stop is a cycle planting *content*: with micro-skills on, a cycle can write facts that are injected into later sessions of **any** repository the plugin has seen. That is why micro-skills ships `off` and `envfacts` is the narrower setting.
- **Tool pruning writes into a checkout.** It adds `permissions.deny` to `<checkout>/.claude/settings.local.json` of the repository whose session's fold produced it, and the path to `.git/info/exclude`. For a worktree-isolated run that checkout is the throwaway worktree, so isolated runs mostly gain nothing and the operator's own checkout is written only by shared-checkout runs. It applies only after the repository has had no session for `toolprune_quiet_minutes` (60). It writes a file the operator did not author into a working tree; `propose` mode exists so the operator can see a list before `auto` acts on it.
- **Its side calls are invisible to every meter.** The loop guard's judge and the micro-skill proposer are `claude -p --no-session-persistence` calls billed to the plan and written to no transcript, so `runs.spent_usd`, the windows and every budget guard here are blind to them. The loop guard therefore ships `off`, not at the plugin's own default of `nudge`; do not move it without a meter that sees these calls.
- **Codex and local runs get nothing.** A local cycle would hand the plugin's model calls an endpoint with no `haiku`, and its turns would teach the repository's Claude history another model's turn length.
