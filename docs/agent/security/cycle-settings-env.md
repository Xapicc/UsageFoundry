# Where a work cycle's settings may send its credential

[← security index](../security.md)

Read before editing `PINNED_CYCLE_ENV`, `cycleEnvPins` or the `--settings` overlay in `buildArgs` (`src/lib/cycleInvocation.ts`), `cycleEnv` or the `envPins` argument at the run loop's `buildArgs` call in `src/lib/orchestrator.ts`, or before adding `--setting-sources` to a work cycle. Every measurement here is in `docs/verification/security-and-sandboxing-telemetry-token.md`, taken on 2.1.310 on 2026-10-25 under board task `a0c412bf`.

- **A work cycle loads its checkout's settings, and their `env` decides where its API requests go.** `runIteration` passes no `--setting-sources`, so the CLI applies the `env` of the cwd's `.claude/settings.json`, its `settings.local.json` and `$CLAUDE_CONFIG_DIR/settings.json` over the environment this app spawned it with. The checkout is repository content: a clone can ship the file, and with `UF_SANDBOX` off an agent's `Bash` writes it for the next cycle. Measured, the file moved the credential to a host it named in five ways, all listed on `PINNED_CYCLE_ENV`. The host it names also answers with the usage the CLI then reports, so the same file fills `installSpend` and every meter that reads the cycle's telemetry. No ingest token or process binding can tell that figure from a true one.

- **The cycle's own `--settings` outranks every one of those files, so the endpoint variables are pinned there and project settings stay loaded.** `cycleEnvPins` reads each variable off `cycleEnv({}, local)`, which is the same function `runIteration` spawns with. A local cycle's pin is therefore its own server, and a stack's exported proxy is pinned like the server's. A variable the environment does not set is pinned to `""`, because leaving it out would let the project's value stand. `""` was measured to read as unset to the CLI and to the node, python, curl and git a `Bash` call starts. With no `ANTHROPIC_BASE_URL` configured, the pin is `""` and requests go to `api.anthropic.com`. Pinning was chosen over `--setting-sources user` because that flag also drops a repository's permissions, hooks and agents and changes agent discovery (`agents.ts`, `../agents-and-templates/agent-references-and-ambient-agents.md`), which is the operator's decision rather than this fix's. The pins share one `--settings` with the sandbox write set, because the CLI keeps only the last one it is given. That means every Claude cycle's argv now carries `--settings`, a stock install's included. `cycleEnvPins`' cases in `orchestrator.test.ts` pin this.

- **No credential is pinned, and none may be.** The overlay is on the argv, and `/proc/<pid>/cmdline` is readable by every process in the container. A project `ANTHROPIC_API_KEY` or `ANTHROPIC_AUTH_TOKEN` replaces or adds the project's own key, sent to the pinned host. That takes nothing of the operator's. The values that are pinned (URLs, proxy URLs, TLS switches) are already in every cycle's environment, where `env` prints them.

- **What is still open.** An install whose server environment turns a third-party provider on keeps that provider's own endpoint variables (`ANTHROPIC_VERTEX_BASE_URL`, `ANTHROPIC_BEDROCK_BASE_URL`, `AWS_ENDPOINT_URL*` and the like) open to a project file. Only the switches are pinned, since `""` for those other keys was not measured and could break such an install. The reviewer, resolver and validator (`spawnAssist` in `review.ts`) run in a checkout with no pins and no `--setting-sources`. The chat keeps the user scope, so a cycle that writes `$CLAUDE_CONFIG_DIR/settings.json` still reaches the chat's `env` unless `UF_LOCK_CLAUDE_HOME` holds (`chat-child-config-files.md`). A project file's hooks and `apiKeyHelper` still run in a cycle; they execute code rather than redirect a request, and were not measured here. Nothing above ran in a booted container as root with winnow on.
