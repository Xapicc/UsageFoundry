What the split already knows

Both endings are one green Completed chip on the list today — StatusMark renders the raw status and FILTERS is keyed on status alone. The run detail page has distinguished them all along: “Used all N work cycles — it never reported the task complete, so there is probably more to do.” Carrying that onto the list is hours of work, has the Needs review segment as an exact precedent, and targets the 29.6% of runs that carry 100% of the measured defect. §1 says do it whether or not the validator is ever built.

Which runs the validator even looks at

Decision 3's recommended default: only completed runs that ended without DONE, and only isolated ones. Everything else shows — not validated and costs nothing.

  • Reported DONE → skipped. 31 of 31 judgeable ones did the work.
  • Not isolated → skipped. No well-defined diff exists; all five worktree columns are null.
  • A continuation → judged on the chain's task or not at all. worktree_base is the chain's by design.

Three ways there is no verdict

  • Refused — over maxConcurrentAssists, or the window. {ok:false, reason}, no row at all.
  • Timed out — REVIEW_TIMEOUT_MS, 10 minutes. A failed row with a sentence.
  • Out of scope — never fired. Nothing anywhere.

The two things (a′) is not free about
  • spawnAssist carries no --max-budget-usd today. Work cycles do, chat turns do, the assist path does not — its only money guard is windowRefusal. An operator-triggered review with no ceiling is tolerable; an automatic one is not. A new validationBudgetUSD, on chatTurnBudgetUSD's precedent of $2.
  • run_reviews.cost_usd is invisible to the install ceiling. installSpend reads runs, workflow_instance_blocks and chat_sessions — and nothing else. The day something fires per finished run, installDailyCostLimitUSD stops meaning what it says. Widening it to read the fourth source is part of this project, not a follow-up.
  • Off by default. It spends money on every finished run, and this app does not ship spenders switched on.

The number the whole thing still rests on

The positive class in the labelled set is two runs, and one of them is held out — so held-out detection is n = 1. Milestone 0 exists to fix exactly that: label ~40 of the 63 cycle-cap endings, two days, and it is a gate rather than a task. If the not-done rate there is at or under 5%, the project stops and the list-and-filter split from §1 is the whole answer.

05

What it deliberately does not do

Every one of these is load-bearing, and each is a thing a reader who meets the design will reach for.

  • Reopen the run. One billed cycle per false negative, systematically, at fleet scale — and it puts an agent that accepts edits back to work unattended on a machine opinion.
  • Move it to needs-review. Overwrites the ladder's statement about who decided.
  • Block a dependent. edgeSatisfied is deliberately not completed && reported_done: if the agent's own claim to have finished is not strong enough to gate that edge, a machine's opinion about that claim certainly is not. An on-validated edge is a different project.
  • Introduce a new run status. needs-review cost a 200-line call-site inventory. Paying it again for an opinion that is wrong in both directions is not a trade worth making.
  • Run the repository's tests. This app has never executed a repository's own commands, and the reviewer is deliberately granted none — --permission-mode plan is the whole posture and a command grant would be the one hole in it. Fenced into M3.
  • Validate non-isolated runs. There is no well-defined diff to read.
  • Validate a chain per-link. Per-run commit boundaries do not exist. Judge the chain or skip it.
  • Validate history. 39% of the sampled branches are already gone; checkouts age out at 7 days.
  • Say the work is correct. Every finished verdict means the change asked for is present, never that it works.
The open exposure, stated rather than closed. The diff is written by an agent and a file in it could contain text addressed to the validator. The mitigations are --permission-mode plan and parsing the verdict from a structured field — not a fix. It is the same exposure review.ts already carries, and the pitch declines to claim otherwise.
