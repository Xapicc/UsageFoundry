The task is a bug report: merge queue rows never update their status, even when a retried merge succeeds. The diff changes the places that would cause that symptom.

- **Worker loop:** `src/lib/mergeQueue.ts` wraps each row in `drainRepo` in a try/catch. A throw now sets the row to `failed` instead of leaving it on `landing`.
- **`git()`:** `src/lib/git.ts` now catches a spawn that throws and reports it as a failed result instead of rejecting.
- **Queue panel:** `src/app/branches/page.tsx` polls the queue whatever it last said, every 15 seconds while idle and every 3 seconds while working. Before, polling stopped once the queue looked idle, so later status changes never reached the page.
- **Route:** `src/app/api/branches/queue/route.ts` now answers through `jsonNoStore`, so a cached response can't hide a status change.
- **Tests and docs:** `src/lib/mergeQueueDrain.test.ts` is new, with a case for the stranded-row failure. `src/lib/git.test.ts` gains a case for `git()` not rejecting. `docs/agent/isolation-and-landing.md` also changed.
